# 共通ブリーフ（調査の前提）

## 依頼者
プログラミング学習中の個人。学習の記録・成果物を公開するサイトと、学習課題として作った
小さな Web アプリを、**すべてゼロから手書き**で作ってしまった。
「最初から良い OSS / ライブラリ / ユーティリティを探して使えばよかった」と後悔しており、
**次に同じものを作るなら何を使うべきか**を知りたい。

## 対象リポジトリの実態（調査対象の現状）

### A. 学習記録サイト `03.learning_site`（The Scholar's Casebook）
- 静的 HTML を **1ページずつ手書き**。ビルドなし、テンプレートエンジンなし。
- 記事は `articles/case-01-xxx.html` のような素の HTML。新記事を足すたびに
  `index.html` のカード一覧を**手で編集**してリンクを追加する運用。
- 共通レイアウト（ヘッダ/フッタ）は各 HTML に**コピペで重複**。
- CSS は `assets/style.css` 一枚を手書き（ヴィクトリア朝テーマ）。
- 検索なし、タグ/カテゴリなし、RSS なし、OGP/構造化データなし、目次(TOC)なし、
  コードハイライトなし、画像最適化なし（PNG をそのまま置いている）。
- 成果物（学習ゲーム）は `02.homework/` から `works/` へ**手動コピー**して二重管理。

### B. 学習課題アプリ `02.homework/05.week5/web`（「かけら」）
端末内 localStorage のみで動く、フレームワーク不使用の静的 SPA。以下を**全部自作**した。
- `scripts/build.js`（約 200 行）が単独のビルドシステム。中身は:
  - **JavaScript minifier を手書き**（文字列/コメント/空白を1文字ずつ走査する自作パーサ）
  - **BPE（Byte Pair Encoding）圧縮を手書き**して JSON 文言データを圧縮し JS に埋め込む
  - `@fontsource` の `400.css` を**正規表現で書き換え**て `@font-face` を生成、
    woff2 を手動コピー（243 ファイル）
  - 静的ファイルの copy / clean、Tailwind CLI の呼び出し、CSS サイズの上限チェック
- アプリ側:
  - ルーター自作（`main.js` が画面名を持ち、history と手動同期。about だけ動的 import）
  - テンプレート自作（テンプレートリテラルで HTML 文字列を組み立て `innerHTML` 代入）
  - 状態管理自作（`state.js` に単一オブジェクト + `Set` の購読者リスト + commit 関数）
  - DOM ヘルパー自作（`lib/dom.js`: querySelector/addEventListener/textContent の薄い包み、
    Blob + a[download] でのファイルダウンロード）
  - 日付ユーティリティ自作（`lib/date.js`: `YYYY-MM-DD` キー生成、日数差、DST 回避で正午固定、
    月キー、直近 N 日など 112 行）
  - 永続化・スキーマ検証自作（`storage/local.js`: localStorage への JSON 直列化、
    読み込み時に手書きの `normalize()` で型検査して壊れたデータを初期値に戻す、
    キーに `v1` を含めた素朴なマイグレーション設計）
  - JSON エクスポート（バックアップ）自作
  - オフライン対応・Service Worker は無し（webmanifest だけある）
- テストは無し。型チェックも無し。Lint/Formatter も無し。CI は GitHub Actions で S3 同期のみ。

### C. インフラ `02.homework/05.week5/infra`
- S3 バケットポリシー / CloudFront レスポンスヘッダポリシー / IAM ロール（OIDC）を
  **生の JSON を手書き**して管理。IaC ツール不使用。デプロイは GitHub Actions から aws-cli。

### D. 学習ゲーム `02.homework/01.week1`
- 「Linux Story Quest」（Linux コマンド学習ゲーム）と「Git Dungeon」（Git 学習 RPG）を
  素の HTML/JS で自作。

## 依頼者の技術的な前提・制約
- 使用言語は HTML / CSS / JavaScript（素の JS）。Node.js 22。npm。
- ホスティングは AWS S3 + CloudFront、CI は GitHub Actions。
- 個人学習用。無料〜低コストであること、日本語のコンテンツを扱うことが前提。
- 学習目的なので「中身を理解できる」ことも重視するが、
  **車輪の再発明で時間を溶かしたくない**というのが今回の問題意識。

## 出力の必須要件（すべての調査に共通）
1. **日本語**で書く。
2. 各候補について必ず: `名前 / 一行説明 / リポジトリ URL / ライセンス / 現在も活発か
   （最終リリース時期の目安）/ このケースで何が置き換わるか / 採用コスト / 注意点・不採用理由`
   を書く。
3. **推測でURLやスター数を書かない**。web search で裏を取れた情報だけを書く。
   確認できなかった項目は「未確認」と明記する。
4. 候補は羅列するだけでなく、**「この人ならこれ」という第一推奨を1つ**明示し、
   なぜ他ではなくそれかを 2〜3 行で述べる。
5. 「自作を続けたほうがよい領域」があるならそれも正直に書く（学習効果・依存の少なさの観点）。
6. Markdown 見出し構造で、後から他のドキュメントと結合しやすい形にする。
