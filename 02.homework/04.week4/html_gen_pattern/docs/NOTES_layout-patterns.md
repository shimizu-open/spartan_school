## 0. そもそもの話

### そもそも「レイアウト」とは何か

**画面のどこに何を置くか**、という配置のこと。
たとえばこの3つは、置いてある中身が同じでも「レイアウトが違う」と言う。

```
   パターンA              パターンB              パターンC
┌─────────────┐      ┌───────┬─────┐      ┌────┬─────┬────┐
│   ロゴ・メニュー │      │       │     │      │    │     │    │
├─────────────┤      │ 本文  │目次 │      │目次│本文 │広告│
│    本文       │      │       │     │      │    │     │    │
├─────────────┤      ├───────┴─────┤      ├────┴─────┴────┤
│   著作権表示   │      │             │      │               │
└─────────────┘      └─────────────┘      └───────────────┘
```

### そもそも HTML と CSS は何が違うのか

ここが分かっていないと、この先の話が全部ぼやける。

| | 役割 | たとえるなら |
|---|---|---|
| **HTML** | **何がそこにあるか**（意味・中身） | 家の間取り図。「ここは台所、ここは寝室」 |
| **CSS** | **それがどう見えるか**（色・大きさ・配置） | 内装。「壁を白く、床は木目」 |

**同じHTMLでも、CSSを差し替えれば見た目が全然変わる。**
逆に言うと、**HTMLの段階では「どこに置くか」をまだ決めていない**。
HTMLで書くのは「これはメニューです」「これは本文です」という**意味の宣言**だけ。

だからこのメモは2段構えになっている。

1. **どんなタグで組むか**（HTML＝意味の話）
2. **それをどう並べるか**（CSS＝配置の話）

### そもそも「型（パターン）」とは何か

Webページの配置は無限に作れるが、**実際に使われている形は数えるほどしかない**。
20年かけて「これが読みやすい」と分かったものが生き残った結果である。

だから**毎回ゼロから考える必要はない**。
「このページは何を見せたいのか」を決めれば、使うべき型はほぼ自動的に決まる。
このメモは、その「数えるほどしかない形」のカタログである。

## 1. 前提：タグの役割分担

型の話に入る前に、使うタグの意味を確定させておく。
ここが曖昧なままだと、どの型も「`div` の集まり」に見えてしまう。

### まず `<div>` の話から

HTMLには `<div>` という「**意味を持たない箱**」がある。何にでも使える。
だから初心者は全部 `<div>` で書いてしまう。それでも**画面上は同じように表示される**。

```html
<!-- ✕ 全部 div。画面には同じように出るが… -->
<div class="header">サイト名</div>
<div class="main">本文</div>
<div class="footer">© 2026</div>
```

```html
<!-- ○ 意味を持つタグを使う -->
<header>サイト名</header>
<main>本文</main>
<footer>© 2026</footer>
```

**なぜ下のほうが良いのか。** 見た目が同じなら意味がないように思えるが、
**画面を見ていない相手**にとっては天と地の差がある。

- **読み上げソフト**（目の見えない人が使う）… 「ここからが本文です」と伝えられる。
  `<div>` だとただの箱なので、どこが本文か分からず、メニューから読み直すはめになる
- **検索エンジン** … どこが本題かを判断してくれる
- **半年後の自分** … `<div class="main">` より `<main>` のほうが一目で分かる

こういう「意味を持つタグ」を**セマンティックタグ**と呼ぶ（semantic ＝ 意味の、という英語）。

### 主なセマンティックタグ

| タグ | 読み方 | 意味 | 1ページに何個？ |
|---|---|---|---|
| `<header>` | ヘッダー | ページの冒頭。サイト名・ロゴ | ページ全体で1つ |
| `<nav>` | ナヴ | **主要な**リンクのまとまり | 複数可。複数なら区別が要る（後述） |
| `<main>` | メイン | そのページ固有の本題。**ヘッダー・フッター・サイドバーを除いた中身** | **必ず1つだけ** |
| `<aside>` | アサイド | 本題から外れても成立する補足（目次・関連記事・広告） | 複数可 |
| `<footer>` | フッター | ページの末尾。著作表示・連絡先 | ページ全体で1つ |
| `<section>` | セクション | 見出しを持つ意味のかたまり | 複数可 |
| `<article>` | アーティクル | **単体で切り出しても成立する**もの（記事・商品カード・コメント） | 複数可 |

### `<section>` と `<article>` の区別（よく迷うところ）

> **この部分だけ切り取って別の場所に貼っても、意味が通るか。**
> 通るなら `<article>`、通らないなら `<section>`。

- ブログの記事本体 → **`<article>`**（SNSに転載しても意味が通る）
- その記事の中の「第2章」 → **`<section>`**（切り出すと前後が分からない）
- 商品一覧の商品1つ → **`<article>`**（それだけで商品として成立する）

### `<div>` を使ってよい場面

`<div>` が悪いわけではない。**「意味はないが、まとめて配置したい」ときは正しい選択**である。
たとえば「本文とサイドバーを横に並べる」ための箱には意味がないので、`<div>` が正解。

```html
<div class="layout">     <!-- 横並びにするためだけの箱。意味はない -->
  <main>本文</main>
  <aside>サイドバー</aside>
</div>
```

**判断基準**：そのまとまりに名前を付けられるか。
「ヘッダー」「本文」と呼べるなら意味があるタグを使う。「並べるための箱」なら `<div>`。

## 2. 型①：1カラム

**カラム = 縦の列**のこと。1カラムは「縦の列が1本しかない」＝横に何も並べない形。

```
┌─────────────┐
│   header    │
├─────────────┤
│    main     │
├─────────────┤
│   footer    │
└─────────────┘
```

### タグ構成

```html
<body>
  <header>…</header>
  <nav>…</nav>
  <main>
    <article>本文</article>
  </main>
  <footer>…</footer>
</body>
```

### CSS

**実は、何も書かなくてもこの形になる。**

HTMLの要素には「ブロック要素」と呼ばれるものがあり、**書いた順に上から下へ積まれる**という
性質を最初から持っている。`<header>` も `<main>` も `<footer>` もブロック要素なので、
CSSを1行も書かなくても縦に積まれる。

だからCSSで足すのは実質2行だけ。

```css
main {
  max-width: 720px;      /* 横幅の上限を720ピクセルにする */
  margin-inline: auto;   /* 左右の余白を自動＝均等に ＝ 中央寄せ */
}
```

`margin`（マージン）は「外側の余白」のこと。
`margin-inline` は「左右の余白」で、`auto` は「余った分を均等に配る」の意味。
結果として中身が中央に来る。

### なぜ最大幅が要るのか

付けないと、大きな画面で1行が画面の端から端まで伸びる。
**1行が100文字を超えると、行の終わりから次の行の先頭に目を戻すときに迷子になる。**
人が快適に読める行長は **40〜75文字**とされている。

### 使いどころと弱点

- **向く**：ブログ記事、ニュース記事、商品紹介ページ、読み物全般
  → 読ませることが目的なら、横にあるものは全部ノイズになる
- **向かない**：目次を常に見せたいページ。長文で今どこを読んでいるか分からなくなる

### 豆知識

スマホでは結局どの型も1カラムに崩れる。
つまり**1カラムだけは崩す必要がない＝一番ラク**。迷ったらここから始めてよい。

## 3. 型②：2カラム（サイドバー付き）

本文の横に細い列を1本足した形。**サイドバー**とは、この横の細い列のこと。

```
┌─────────────┐
│   header    │
├───────┬─────┤
│ main  │aside│
├───────┴─────┤
│   footer    │
└─────────────┘
```

### タグ構成

```html
<body>
  <header>…</header>
  <div class="layout">        <!-- 横並びにするためだけの箱。意味はないので div -->
    <main>本文</main>
    <aside>目次・関連記事</aside>
  </div>
  <footer>…</footer>
</body>
```

ここで**初めて `<div>` が正当化される**。
「`main` と `aside` を横に並べる」のは見た目の都合であって意味ではないので、
意味を持つタグを使う理由がない。

### CSS：ここで Flexbox が登場する

**Flexbox（フレックスボックス）** は「要素を一列に並べるための仕組み」。
親要素に `display: flex` と書くと、**その中の子要素が横一列に並ぶ**。

```css
.layout { display: flex; gap: 40px; }   /* 中身を横並びに。gap は要素同士のすき間 */
main    { flex: 1; min-width: 0; }
aside   { flex: 0 0 240px; }
```

`flex:` に続く3つの値は、順に次を意味する。

| 位置 | 名前 | 意味 |
|---|---|---|
| 1つめ | 伸びる度合い | 余った幅をどれだけもらうか。0なら伸びない |
| 2つめ | 縮む度合い | 幅が足りないときどれだけ縮むか。0なら縮まない |
| 3つめ | 基準の幅 | 元々の幅 |

- `flex: 1` … 「余った幅を全部もらう」（`flex: 1 1 0%` の省略形）
- `flex: 0 0 240px` … 「伸びない・縮まない・240px」＝**固定幅**

### `min-width: 0` という謎の1行

これは初心者が2カラムで**最初に踏む地雷**なので、独立して説明する。

**症状**：長いURLや横に広い表を本文に置くと、レイアウトが崩れてサイドバーが押し出される。

**原因**：Flexbox の子要素には「**中身より小さくならない**」という初期設定がある。
本文の中に画面幅より長い文字列があると、本文の箱がそれに合わせて膨らみ、
サイドバーの場所を奪ってしまう。

**対処**：`min-width: 0` を書く。これは「中身より小さくなってもよい」という宣言。
**おまじないではなく、初期設定の解除である。**

### サイドバーは右か左か

**読み物なら右が基本。**
人は左上から読むので、**本文を先に目に入れたい**から。

左に置くのは「ナビが主役」のアプリ系（管理画面など）。
操作するものは、操作を先に見せたほうがよいため。

### 使いどころと弱点

- **向く**：技術ドキュメント、長い解説記事、商品一覧の絞り込み
- **向かない**：スマホ利用が大半のページ
  → 狭い画面では横に並べられず、サイドバーが本文の下に落ちる。常に見える意味が消える

## 4. 型③：折りたたみサイドパネル

サイドバーをボタンで開いたり閉じたりできるようにした形。管理画面でよく見る。

```
開いた状態              閉じた状態
┌─────────────┐        ┌─────────────┐
│   header    │        │   header    │
├─────┬───────┤        ├──┬──────────┤
│ nav │ main  │        │▪ │  main    │   ← アイコンだけ残る
├─────┴───────┤        ├──┴──────────┤
│   footer    │        │   footer    │
└─────────────┘        └─────────────┘
```

### タグ構成

```html
<body>
  <header>
    <button id="toggle" aria-expanded="true" aria-controls="side">
      ☰ メニュー
    </button>
  </header>
  <div class="layout">
    <aside id="side" data-open="true">     <!-- 開いているかを属性で持つ -->
      <nav aria-label="サイドメニュー">…</nav>
    </aside>
    <main>本文</main>
  </div>
  <footer>…</footer>
</body>
```

`data-open="true"` の `data-` で始まる属性は、**自分で好きに作れる印**である。
HTMLの正式な属性ではないが、`data-` で始めれば何を書いてもよい決まりになっている。
ここでは「今このサイドバーは開いている」という状態を記録するために使っている。

### ここが一番大事：JSとCSSの役割分担

開閉には JavaScript（以下JS）が必要になる。**そのときの書き方が2通りある。**

```js
// ✕ よくない書き方：見た目をJSが直接いじる
side.style.width = "56px";
```

```js
// ○ 正しい書き方：JSは「状態」を変えるだけ
side.dataset.open = "false";
toggle.setAttribute("aria-expanded", "false");
```

```css
/* 見た目の定義はCSS側に全部書いておく */
aside { width: 240px; transition: width .3s; }        /* 開いているとき */
aside[data-open="false"] { width: 56px; }             /* 閉じているとき */
```

`aside[data-open="false"]` は「`data-open` が `false` になっている `aside`」という指定。
**属性の値でCSSを切り替えられる。**

> **JSの仕事は「今どういう状態か」を記録すること。**
> **CSSの仕事は「その状態がどう見えるか」を決めること。**

**なぜこう分けるのか。**
JSで直接 `width` を書いていると、後から幅を変えたくなったときに
「CSSに書いてあるのか、JSに書いてあるのか」を探し回ることになる。
役割を分けておけば、見た目を変えたいときは**CSSだけ見ればよい**。

### 開閉ボタンは必ず `<button>`

`<div onclick="...">` でもクリックには反応するので、動いてしまう。**だが使ってはいけない。**

`<div>` は**キーボードのTabキーでフォーカスできない**。
つまりマウスが使えない人（手が不自由な人、視覚障害者）は、そのボタンに到達できず、
**永久にメニューを開けない**。

`<button>` は最初からキーボードで操作できる。Enterでも Space でも押せる。
**「押せるものは `<button>`」と覚えてよい。**

### `aria-expanded` とは

`aria-`（アリア）で始まる属性は、**読み上げソフトに追加の情報を伝えるためのもの**。
`aria-expanded="true"` は「今これは開いています」の意味。

見た目では開いているか一目で分かるが、画面を見ていない人には分からない。
だから**JSで開閉するとき、見た目と一緒にこの属性も更新する**必要がある。

### 使いどころと弱点

- **向く**：管理画面、ダッシュボード、メニュー項目が多いサイト
- **向かない**：ページ数が少ないサイト
  → 開いたり閉じたりする手間のほうが、広がる本文の幅より大きい

**よくある失敗**：閉じてアイコンだけになると、**何のアイコンか分からなくなる**。
`title` 属性を付けて、マウスを載せたら名前が出るようにしておく。

## 5. 型④：ヘッダーにナビメニュー

上部のバーにロゴとメニューを並べる形。ほぼすべてのWebサイトがこれ。

```
広い画面                        狭い画面
┌──────────────────┐          ┌──────────┐
│ LOGO   A  B  C   │          │ LOGO  ☰  │
├──────────────────┤          ├──────────┤
│      main        │          │  main    │
└──────────────────┘          └──────────┘
```

### この型だけ「層」が違う

**重要な気づき**：この型は**骨格の型ではなく、ナビゲーションの型**である。

1カラムにも2カラムにも聖杯にも重ねられる。
課題のリストでは5つが横並びに書かれているが、**この項目だけ種類が違う**。

```
【骨格】ページを縦にどう割るか       1カラム / 2カラム / 聖杯
【ナビ】メニューをどう出すか         ヘッダーナビ / 折りたたみサイドパネル
```

1つのページは「骨格から1つ ＋ ナビから1つ」の**組み合わせ**でできている。

### タグ構成

```html
<header class="site-header">
  <a class="logo" href="/">サイト名</a>
  <button class="hamburger" aria-expanded="false" aria-controls="gnav">
    ☰ MENU
  </button>
  <nav id="gnav" aria-label="メインメニュー">
    <ul>
      <li><a href="#a">項目A</a></li>
      <li><a href="#b">項目B</a></li>
    </ul>
  </nav>
</header>
```

### リンクは必ず `<ul>` / `<li>` で囲む

`<ul>` は「順序のないリスト」、`<li>` はその1項目。
見た目だけなら `<a>` を裸で並べても同じように出るが、**囲むべき**である。

理由：「これはリンクが3つ並んだ**集合**だ」という情報が構造に残る。
読み上げソフトは「**リスト、3項目**」と教えてくれるので、
聞いている人は「メニューが3つあるんだな」と分かる。
裸で並べると、どこまでがメニューか分からない。

### CSS

```css
.site-header {
  display: flex;                    /* 中身を横並びに */
  justify-content: space-between;   /* 左端と右端に振り分ける */
  align-items: center;              /* 縦方向は中央に揃える */
  position: sticky;                 /* スクロールしても画面上部に貼り付く */
  top: 0;
}
.hamburger { display: none; }       /* 広い画面では隠しておく */

@media (max-width: 640px) {         /* 画面幅が640px以下のときだけ適用 */
  .hamburger { display: block; }    /* ハンバーガーを出す */
  nav { transform: translateY(-100%); }          /* メニューを画面の上に隠す */
  .site-header.is-open nav { transform: none; }  /* 開いたら降りてくる */
}
```

`@media (max-width: 640px)` は **メディアクエリ**といい、
「画面幅が◯◯以下のときだけ、このCSSを適用する」という指定。
スマホ対応の基本の道具。

`position: sticky` は「**普段は普通に流れるが、画面の端まで来たらそこで止まる**」という指定。
上部に固定したいヘッダーで定番。

### つまづきやすい点

**① `scroll-padding-top` を忘れる**

ヘッダーを固定すると、ページ内リンク（`href="#works"` のようなもの）で飛んだとき、
**飛んだ先の見出しが固定ヘッダーの下に隠れる**。

```css
html { scroll-padding-top: 64px; }   /* ヘッダーの高さぶん手前で止める */
```

**② `☰` だけ置く**

あの3本線の記号は「ハンバーガーメニュー」と呼ばれ、押せばメニューが出ると
**知っている人には**通じる。だが知らない人には通じない。
`MENU` の文字を添えるのが今の主流。

### 目安

メニューが **7個以下**ならこの型で足りる。
それを超えるなら、横に並べきれないので折りたたみサイドバーを検討する。

## 6. 型⑤：聖杯レイアウト（Holy Grail、3カラム）

本文を左右のサイドバーで挟んだ3列の形。

```
┌───────────────┐
│    header     │
├────┬─────┬────┤
│nav │main │side│
├────┴─────┴────┤
│    footer     │
└───────────────┘
```

### タグ構成

```html
<body>
  <header>…</header>
  <div class="layout">
    <nav aria-label="サイトメニュー">左サイド</nav>
    <main>本文</main>
    <aside>右サイド</aside>
  </div>
  <footer>…</footer>
</body>
```

### CSS：ここで Grid が登場する

**Grid（グリッド）** は「格子状に配置するための仕組み」。
Flexbox が「一列に並べる」道具なら、Grid は「方眼紙に置く」道具。

```css
.layout {
  display: grid;
  grid-template-columns: 200px 1fr 200px;   /* 3つの列の幅を指定 */
  gap: 32px;
}
```

**この1行で終わる。**
`grid-template-columns` は「列をどう分けるか」の指定で、書いた数だけ列ができる。
`1fr` の `fr` は fraction（分数）の略で、「**余った幅を全部**」の意味。
つまり左右を200pxずつ固定して、中央に残り全部を渡している。

### 「聖杯」という名前の由来

聖杯（Holy Grail）＝ 伝説上の、誰も手に入れられない杯のこと。
なぜレイアウトがそう呼ばれたのか。

昔は `float`（フロート）という、本来は「画像の横に文字を回り込ませる」ための機能を
無理やり使ってレイアウトを組んでいた。この方法では、

> **本文をHTMLの先頭側に書きつつ、画面では真ん中に表示する**

という両立が非常に難しかった。
なぜ本文を先に書きたいかというと、**検索エンジンや読み上げソフトはHTMLの順に読む**から。
メニューを延々と読まされてから本文に辿り着くのでは困る。

この「HTMLの順序」と「画面上の位置」を両立させることが至難で、
**誰も到達できない聖杯**と皮肉られた。CSS Grid はそれを1行で解決した。

### 使いどころと弱点

- **向く**：ニュースポータル、情報量が非常に多いサイト
- **向かない**：**中身が少ないうちは使ってはいけない**
  → カラムは増やすほど本文が狭くなる。右カラムを埋めるものが無いなら2カラムのほうが優れている

## 7. Flexbox と Grid の使い分け（混乱しやすいところ）

型②で Flexbox、型⑤で Grid が出てきた。**どちらも「並べる」道具**なので混乱しやすい。

| 道具 | ひとことで | 使う場面 | 覚え方 |
|---|---|---|---|
| **何も書かない**（通常フロー） | ブロック要素は上から下に積まれる | 1カラム、文章 | **足りているなら何も書かない** |
| **Flexbox** | **一列**に並べて余りを配り合う | ヘッダーの左右振り分け、2カラム、ボタンの横並び | 「1本の線に並べる」 |
| **Grid** | **格子**に配置する | 3カラム、カード一覧、ダッシュボード | 「方眼紙に置く」 |

**判断基準**：
- 「1方向に並べたい」→ **Flexbox**
- 「縦横どちらも制御したい」→ **Grid**

2カラム程度ならどちらでも書ける。この教材では対比のために
型②を Flexbox、型⑤を Grid で書き分けている。

### おまけ：カードを並べるときの魔法の1行

```css
.cards {
  display: grid;
  grid-template-columns: repeat(auto-fill, minmax(220px, 1fr));
  gap: 16px;
}
```

読み下すと「**220px を下限として、入るだけの列を自動で作り、余りは均等に分配する**」。
画面が広ければ4列、狭ければ2列、スマホなら1列に**勝手に変わる**。
メディアクエリを1行も書かずに済むので、今風の書き方の代表格として覚えておくとよい。

## 8. 課題の例示質問への答え

### Q. ブログ記事のページってどういうタグ構成が定番？

```html
<body>
  <header>サイト名</header>
  <nav aria-label="メインメニュー">…</nav>
  <div class="layout">
    <main>
      <article>                          <!-- 記事全体を article で包む -->
        <header>                         <!-- 記事の中にも header を置ける -->
          <h1>記事タイトル</h1>
          <time datetime="2026-07-25">2026年7月25日</time>
        </header>
        <section><h2>見出し1</h2><p>…</p></section>
        <section><h2>見出し2</h2><p>…</p></section>
        <footer>タグ・著者情報</footer>   <!-- 記事の footer -->
      </article>
    </main>
    <aside>
      <nav aria-label="目次">…</nav>
      <section><h2>関連記事</h2>…</section>
    </aside>
  </div>
  <footer>© 2026</footer>
</body>
```

押さえどころは3つ。

**① 記事本体は `<article>`**
RSSに流したりSNSに転載しても意味が通るから。

**② `<header>` と `<footer>` は入れ子にできる**
「ページ全体のヘッダー」と「記事のヘッダー」は別物。
`<article>` や `<section>` の中に置いたヘッダーは、その範囲だけのものとして扱われる。

**③ `<time datetime="2026-07-25">` を使う**
画面に出るのは「2026年7月25日」でも、`datetime` に書いた形式で機械が読む。
表記ゆれ（`7/25`、`令和8年7月25日`）があっても、機械には統一形式で伝わる。

### Q. 管理画面みたいな折りたたみサイドバーはどう作る？

型③の構成そのままだが、管理画面ならではの追加要件がある。

```html
<div class="layout">
  <aside id="side" data-open="true">
    <nav aria-label="管理メニュー">
      <ul>
        <li>
          <a href="#" title="ダッシュボード">
            <span class="icon">▤</span>
            <span class="label">ダッシュボード</span>
          </a>
        </li>
      </ul>
    </nav>
  </aside>
  <main>…</main>
</div>
```

```css
aside[data-open="false"] .label { display: none; }  /* 畳んだらアイコンだけ */
```

- **アイコンとラベルを別の要素に分ける**
  → 畳んだときラベルだけ消せるようにするため。同じ要素に入れていると分離できない
- **`title` 属性を付ける**
  → 畳んだ状態でマウスを載せると名前が出る。
  これが無いと「何のアイコンか分からない問題」が必ず起きる
- **スマホでは幅を縮めるのではなく、画面の外から重ねる**（ドロワーという形式）
  → 狭い画面で56px取られると本文が読めなくなるため

## 9. 「どの構成を選んだか・なぜか」の答え方

課題が最終的に求めているのはここ。

> **選んだ理由より、捨てた理由のほうが説得力を持つ。**

「これを選びました」だけだと、他を知らないのか、比べた上で選んだのかが伝わらない。
**捨てた型とその理由を言えると、比較した証拠になる。**

### 実際に作った年表ページ（`chronology.html`）についての説明

> **年表ページには1カラムを選びました。**
> 時系列は縦一本に並ぶのが最も読みやすく、
> 横に何かを置くと目線が左右に振られて読む流れが切れるからです。
>
> 2カラムも検討しましたが、**サイドバーに置くものが無かった**のでやめました。
> 目次を置く案は、年表そのものが目次のような一覧性を持っているので重複します。
>
> 聖杯は最初から外しました。
> **右カラムに置く情報が無く、空のカラムは本文を狭めるだけ**だからです。
>
> ナビは、ページ数が2つしかないのでヘッダーナビにしました。
> 折りたたみサイドパネルは、
> **畳んだり開いたりする操作コストが、得られる本文の幅より大きい**と判断しました。
> 項目が8個を超えたら考え直します。

### この形をテンプレートにする

```
選んだ型 → その理由 → 検討して捨てた型 → 捨てた理由
```

## 10. 用語集

分からない言葉が出てきたらここを見る。

| 用語 | 意味 |
|---|---|
| **カラム** | 縦の列。「2カラム」＝縦の列が2本 |
| **セマンティックタグ** | 意味を持つタグ。`<header>` `<main>` など。semantic＝意味の |
| **ブロック要素** | 書いた順に上から下へ積まれる性質を持つ要素。`<div>` `<p>` `<section>` など |
| **Flexbox** | 要素を一列に並べる仕組み。`display: flex` |
| **Grid** | 要素を格子状に配置する仕組み。`display: grid` |
| **`fr`** | Grid で使う単位。fraction（分数）の略で「余った幅の取り分」 |
| **`ch`** | 文字の幅を基準にする単位。`65ch` ＝ おおよそ65文字ぶんの幅 |
| **`gap`** | 並べた要素同士のすき間 |
| **`margin`** | 要素の**外側**の余白 |
| **`padding`** | 要素の**内側**の余白（枠と中身のあいだ） |
| **メディアクエリ** | 画面幅などの条件でCSSを切り替える仕組み。`@media (max-width: 640px)` |
| **ブレークポイント** | メディアクエリで切り替える境目の幅。640px、768px などがよく使われる |
| **`position: sticky`** | 普段は普通に流れ、画面の端まで来たらそこで止まる指定 |
| **`position: absolute`** | 親要素を基準に、指定した座標へ置く指定 |
| **`transform`** | 要素を移動・回転・拡大する指定。`translateY(-100%)` で上に隠すなど |
| **`transition`** | 変化をなめらかにする指定。`transition: width .3s` で幅の変化が0.3秒かけて起こる |
| **疑似要素** | `::before` `::after`。HTMLに要素を足さずに、CSSだけで飾りを追加する仕組み |
| **`data-` 属性** | 自分で好きに作れる印。`data-open="true"` など。状態の記録に使う |
| **`aria-` 属性** | 読み上げソフトに追加情報を伝える属性。`aria-expanded` など |
| **フォーカス** | キーボード操作で今どの要素を選んでいるか。Tabキーで移動する |
| **ドロワー** | 画面の外から滑り込んでくるメニュー。引き出し（drawer）から |
| **ハンバーガーメニュー** | `☰` のこと。3本線がハンバーガーに見えることから |
| **ページ内リンク** | 同じページの別の場所へ飛ぶリンク。`href="#works"` の形 |

## 11. 実装で使った型（このディレクトリの成果物）

| ページ | 骨格 | ナビ | 中身 |
|---|---|---|---|
| `../index.html` エントランス | 1カラム | ヘッダーナビ＋ハンバーガー | ヒーロー＋カードグリッド |
| `../chronology.html` 年表 | 1カラム | ヘッダーナビ＋ハンバーガー | タイムライン |

### 採用しなかった型と理由

- **聖杯（3カラム）** … 右カラムに置くほどの情報量がない。空の列は本文を狭めるだけ
- **折りたたみサイドパネル** … 全2ページでは、開閉の操作コストが得られる幅より大きい
- **2カラム** … 現状のページはどちらも「読ませる」ことが目的で、
  常時表示したい目次や操作が無い。今後、作品総覧（絞り込みが要る）で採用予定

**「使わない判断ができること」も理解の証拠である。**
埋めるものが無いのに3カラムにする、ページが2つしかないのに折りたたむ、
といったことをしないために、それぞれの型が**何を解決する道具なのか**を知っておく。
