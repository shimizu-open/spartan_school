# 仕様書 STEP7：仕上げと検証

STEP6 までに5ページと画像が揃っている。今回は**検証と、残りのドキュメントを作って完成させる**。

**このステップでは新しい機能を作らない。** 直すことと、書くことだけ。

---

## 作る／触るファイル

```
html_gen_pattern/
├── README.md          ← 【新規】成果物の歩き方
├── REPORT.md          ← 【新規】検証結果
├── GUIDE.md           ← 【修正】実態に合っていない章を直す
└── 各HTML/CSS/JS      ← 【修正】検証で見つかった問題の修正のみ
```

## 1. 検証（先にやること）

以下を**実際に手を動かして確認する**。確認せずに「問題なし」と書かないこと。
問題が見つかったら、報告するだけでなく**その場で直す**。

### リンク

- [ ] 5ページすべての相対リンクが、実在するファイルを指しているか
      （ファイルの存在をコマンドで確認する）
- [ ] 各ページのヘッダーで、現在地に `aria-current="page"` が付いているか
- [ ] `index.html` の館内案内カード4枚すべてがリンクになっているか（「準備中」が残っていないか）

### 構造

- [ ] 各ページの `<h1>` が1つだけか
- [ ] 見出しレベルの飛び（h2 の次が h4 など）がないか
- [ ] `<main>` が各ページに1つだけか
- [ ] 複数ある `<nav>` に `aria-label` が付いているか
- [ ] 5ページのヘッダーのHTMLが同一の形か（差分を取って確認する）

### 禁止事項

- [ ] JS に `element.style` への直接代入が1箇所もないか（grep で確認する）
- [ ] `style="..."` のインラインスタイルがないか
- [ ] レイアウト目的の `<table>` / `float` がないか
- [ ] `var` が使われていないか
- [ ] 外部ライブラリ・CDN・Webフォントへのリクエストがゼロか

### 表示

- [ ] **320px / 768px / 1440px の3幅で、横スクロールが発生しないか**
- [ ] 各ページが狭い画面で定義どおりの順序に縦積みされるか
- [ ] 本文と背景のコントラスト比が 4.5:1 以上か

### 操作

- [ ] キーボードだけで全ページの全機能を操作できるか
      （ハンバーガー／人物の切替と矢印キー／絞り込み／地図のホットスポット）
- [ ] `aria-expanded` が実際の開閉状態と一致して更新されるか
- [ ] **JavaScript を無効にしても、全ページの情報が読めるか**
- [ ] ブラウザのコンソールにエラー・警告が出ていないか

### 内容の正確さ（最重要）

- [ ] **`CONTENT.md` と全ページの記述を1件ずつ突き合わせる**
      （年号14件、人物9人、作品9冊、地名6か所）
- [ ] `CONTENT.md` にない事実が混入していないか
- [ ] `CONTENT.md` §6 の禁止事項に違反がないか
      （収録編数・作中年・生年・地名追加・人物追加・あらすじ）

## 2. `GUIDE.md` の修正

中断した実行の名残で、**実態と合っていない箇所がある**。

### §8「ベイカー街資料館での実際の選択と、その理由」

実際に作った5ページに合わせて書き直す。各ページについて次を書くこと。

- どの型を選んだか
- なぜその型か（1段落）
- **他のどの型を検討し、なぜ捨てたか**（ここが最重要）
- 実装してみて分かった、その型の意外な難しさ

### §10「実装した5パターンへの索引」

`patterns/` ディレクトリは**作らないことにした**（資料館の各ページが既に型を弾き分けており、
役割が重なるため）。この章は削除するか、
「資料館の5ページへの索引」に書き換えること。

### 全体

- 本文中に、存在しないファイルやページへの参照が残っていないか確認する

## 3. `README.md`（新規）

### 含める内容

1. **この成果物は何か**（3行）
2. **ディレクトリ構成の図**と、各ファイルの役割
3. **何から読めばいいか**
   `NOTES_layout-patterns.md` → `index.html` を開く → `GUIDE.md` → `ROADMAP.md`
4. **各ページで選んだ型と、その理由**
   → **学習者が課題提出でそのまま口頭で話せる文章**として書くこと。
   採用しなかった型（聖杯・折りたたみサイドパネル）と、なぜ捨てたかも必ず含める
5. **学んだことの要約**（箇条書き10項目程度）

### 4番の書き方の例

> 年表ページには1カラムを選びました。時系列は縦一本に並ぶのが最も読みやすく、
> 横に何かを置くと目線が左右に振られて読む流れが切れるからです。
> 2カラムも検討しましたが、サイドバーに置くものが無かったのでやめました。

この「**選んだ型 → その理由 → 検討して捨てた型 → 捨てた理由**」の形を全ページ分書く。

## 4. `REPORT.md`（新規）

### 含める内容

1. **§1 検証の結果**
   - 各項目に ✅／❌
   - ❌ なら、何が問題で、どう直したか（または直せなかった理由）
   - **確認していない項目に ✅ を付けないこと**
2. **実装中に迷った点と、どう判断したか**
3. **型を弾き分けてみて分かったこと**
   - 特に、2カラム（Flexbox）と地図（スプリット）を書き比べて気づいた違い
   - マスター＋ディテールが狭い画面で成立しなかったこと
4. **画像生成の結果**（成功／失敗、使ったプロンプトの要旨）
5. **仕様書の記述で曖昧だった箇所**（あれば）
6. **残っている問題**（直せなかったもの。隠さずに書く）
