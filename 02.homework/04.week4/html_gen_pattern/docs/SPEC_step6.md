# 仕様書 STEP6：画像を生成して組み込む

STEP5 までに5ページすべてが揃い、画像なしで動いている。
今回は**画像を11枚生成して組み込む**。

## なぜこの順番なのか

画像を先に入れると、レイアウトが崩れているのか画像が悪いのか切り分けられなくなる。
**構造が固まってから化粧をする。**

STEP3〜5 で `aspect-ratio` により領域は確保済み、`<img>` タグも正しいパスで書いてある。
今回は**画像を置けば表示される状態**のはずである。

---

## 作る／触るファイル

```
html_gen_pattern/
├── images/            ← 【新規】生成した画像11枚
├── style.css          ← 【修正】画像に合わせた微調整のみ
└── 各HTML             ← 【修正】必要なら alt の調整のみ
```

**構造の変更はしないこと。** 画像を入れた結果どうしても必要になった調整だけ行う。

## 2. 画像生成の厳守事項

### 文字を描かせない
生成画像の文字は必ず崩れる。**地図の地名も含めて、画像内に文字を一切入れない。**
文字はすべてHTML側で乗せる。

### 実在の人物に似せない
ホームズは映像化が非常に多く、特定の俳優に似た画像が出ると肖像権の問題が生じる。
**匿名的・シルエット的な人物像にすること。**
既存の映像作品・イラストの構図を模倣しない。

### ポートレート9枚は画風を完全に統一する
並べたときにバラバラだと資料館に見えない。
**同じプロンプトの骨格を使い回し、以下を揃えること。**

- 画風（例：セピアの銅版画調、粒子のある古写真調 など。どれか1つに決める）
- 照明の向きと強さ
- 構図（胸から上、同じ画角）
- 背景の処理（同じ暗さ・同じ質感）

### ファイルサイズ
- `hero-fog.jpg` と `map-london.jpg` … **500KB 以下**
- ポートレート9枚 … **各 200KB 以下**

超える場合は縮小・再圧縮すること。
外部リクエストゼロで動かすため、画像はローカルに置く。base64 埋め込みはしない。

## 3. 組み込み後の確認と調整

### ヒーロー
- 画像の上に暗いグラデーションを重ね、**文字とのコントラスト比 4.5:1 以上**を確保する
- 画像が縦横比の違う画面でも破綻しないよう `object-fit: cover` を使う
- **`loading="lazy"` を付けない**（最初に見えるものなので、遅延読み込みは逆効果）

### 地図
- ホットスポットの位置が、生成された地図の絵と合っているか確認する
- 合っていなければ `.pin--*` クラスの `top` / `left` の `%` を調整する
- **`loading="lazy"` を付けない**（ページの主役なので）

### ポートレート
- `loading="lazy"` を付ける（初期表示では1人分しか見えないため）
- 9枚の見た目が揃っているか、実際に並べて確認する

### `alt` の見直し
- 装飾目的のものは `alt=""` にする
- 情報を持つものは内容を説明する文にする
- **「〜の画像」と書かない**（読み上げソフトが「画像」と二重に言うため）

---

## 4. 生成に失敗した場合

**無理に代替画像を探さないこと。**

- CSS のグラデーション、または頭文字のイニシャル表示で代替する
- **画像がなくてもレイアウトが崩れないことを確認する**
- 失敗した枚数と理由を報告する

画像は「あると良いもの」であって、無いと成立しないものにはしない。

---

## 5. 完了時に報告すること

- 生成できた枚数／失敗した枚数と理由
- 使ったプロンプトの要旨（ポートレートで共通化した骨格の部分）
- 各画像のファイルサイズ
- ヒーローのコントラスト比を確認した結果
- 地図のホットスポット位置を調整したかどうか
