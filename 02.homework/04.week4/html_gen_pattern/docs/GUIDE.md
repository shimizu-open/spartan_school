# レイアウトパターン教科書

## 1. はじめに — このドキュメントの読み方

この教科書の目的は、見た目をまねることではなく、ページに合う「型」を選べるようになることです。
ここでいうレイアウトは、文章や部品を画面のどこへ置くかという設計を指します。
最初からCSS（見た目を指定する言語）の名前を暗記する必要はありません。
先に「何をしてもらうページか」を決め、その目的に合う型を選びます。

読む順番は、まず第2章で3つの層を知り、次に興味のあるパターンを1つ読みます。
その後、第6章のフローチャートで型を選び、第7章でCSSの道具を選びます。
最後に第10章から実物を開き、ブラウザ幅を広げたり狭めたりしてください。
同じ人物原稿でも、型が変わると目線の動きや使いやすさが変わることが分かります。

大切なのは、複雑な型ほど優れているわけではないということです。
必要のない列や操作を足すと、本文が狭くなり、読者が迷う原因になります。
「通常フローで十分なら何もしない」も、根拠のある立派な設計判断です。

## 2. 大前提：レイアウトには3つの層がある

Webページの型は、すべてを同じ種類として比べるものではありません。
次の3つの層に分けると、何を選んでいるのかが見えるようになります。

| 層 | 決めること | 例 |
|---|---|---|
| 層1：骨格 | ページ全体を縦方向に何列へ分けるか | 1カラム、2カラム、聖杯 |
| 層2：ナビゲーション | 別の場所へ移るメニューをどう出すか | ヘッダーナビ、ドロワー |
| 層3：中身 | 本文の内側で情報をどう並べるか | カード、タイムライン |

カラムは「縦の列」という意味です。
ナビゲーションは、ページや項目へ移動するための案内です。
1つのページは、原則として「層1から1つ、層2から1つ、層3から必要な数」を組み合わせます。
たとえば年表は「1カラム＋ヘッダーナビ＋タイムライン」です。

初心者がやりがちな失敗は、3つの層を混ぜて「カードと2カラムのどちらがよいか」と比べることです。
カードは本文内の並べ方、2カラムはページの骨格なので、同時に使えます。
まず層を特定すれば、比較する相手を間違えません。

## 3. 層1：骨格のパターン

### ① 1カラム（シングルカラム）

**アスキー図**
```text
┌──────────┐
│  header  │
├──────────┤
│   main   │
├──────────┤
│  footer  │
└──────────┘
```

**ひとことで言うと**
情報を上から下へ1列に積む、最も単純な骨格です。

**なぜこの形が生まれたか**
文章を読むとき、横の列は目線を分岐させます。
読むことが主目的なら分岐をなくし、本文だけに集中できる形が合理的です。

**向いている場面**
- ブログ記事、ニュース記事、読み物、サービス紹介LP（1枚で内容を伝えるページ）
- スマートフォンで読む人が多いページ

**向かない場面**
- 長い目次や絞り込みを常に見せたいページ。読者が現在地を見失います。
- 多数の数値を同時比較する管理画面。縦に長くなりすぎます。

**初心者がやりがちな失敗**
- 本文幅を制限せず、大画面で1行が長くなる → 目を左右へ動かす距離が増える → `max-width: 65ch`で直します。
- 単純では物足りないと列を増やす → 読む邪魔になる → ページの目的が文章なら1列を保ちます。

**実装の核心**
```css
main { max-width: 65ch; margin-inline: auto; }
```
`ch`は「0」という文字のおよその幅を1とする単位です。
`margin-inline: auto`は左右の余白を均等にして中央へ置きます。
FlexboxもGridも不要です。

**関連**：②2カラムは、常に見せる補助情報があるときだけ選びます。

### ② 2カラム（サイドバー付き）

**アスキー図**
```text
┌──────────────┐
│    header    │
├─────────┬────┤
│  main   │side│
├─────────┴────┤
│    footer    │
└──────────────┘
```

**ひとことで言うと**
本文の横に、目次や絞り込みを置く細い列を添える骨格です。

**なぜこの形が生まれたか**
本文を見ながら何度も使う操作を、スクロールして探し直さずに済ませるためです。
読み物では本文を先に目へ入れたいので、補助列は右が基本です。

**向いている場面**
- 技術ドキュメントの目次、長い解説記事の関連情報
- 商品一覧や作品一覧の絞り込み

**向かない場面**
- スマートフォン利用が大半のページ。補助列が下へ落ち、同時に見える利点が消えます。
- 補助情報が数行しかないページ。空いた列が本文を狭めます。

**初心者がやりがちな失敗**
- 本文が横にはみ出す → Flexboxの子は中身より縮みにくい → `min-width: 0`を本文へ指定します。
- 読み物の左に補助列を置く → 本文より先に目へ入る → ナビが主役でない限り右へ置きます。

**実装の核心**
```css
.layout { display: flex; }
main { flex: 1; min-width: 0; }
aside { flex: 0 0 240px; }
```
Flexboxは要素を1本の線上へ並べ、余った幅を分ける仕組みです。
`flex: 1`は本文が余りを受け取り、`flex: 0 0 240px`は補助列を240pxに保ちます。

**関連**：④マスター＋ディテールは、左右が補助と本文ではなく「選択肢と詳細」の関係です。

### ③ 聖杯レイアウト（Holy Grail、3カラム）

**アスキー図**
```text
┌───────────────┐
│    header     │
├────┬─────┬────┤
│nav │main │side│
├────┴─────┴────┤
│    footer     │
└───────────────┘
```

**ひとことで言うと**
本文を左右2本の補助列で挟む、3カラムの骨格です。

**なぜこの形が生まれたか**
昔のCSSでは、本文をHTML上で先に置きながら画面中央へ表示するのが難題でした。
伝説の杯ほど手に入れにくいという皮肉から「聖杯」と呼ばれました。
今はCSS Grid（方眼紙のように行と列を扱う仕組み）で簡潔に作れます。

**向いている場面**
- ナビ、本文、関連情報を同時に見せるニュースポータル
- 3列すべてに継続して十分な情報がある大規模サイト

**向かない場面**
- 中身の少ない個人サイト。空の列が本文を狭めるだけなので、まず不要です。
- スマートフォン主体のページ。結局1列へ戻す必要があります。

**初心者がやりがちな失敗**
- 有名な型だから使う → 左右を埋める情報がない → 先に各列の役割を書き出し、空なら列を減らします。
- `order`で表示順だけ変える → 読み上げ順と見た目がずれる → HTMLでも中央に本文を書きます。

**実装の核心**
```css
.layout { display: grid; grid-template-columns: 200px 1fr 200px; }
```
`1fr`は、固定した左右の200pxを引いた残り幅を中央へ渡す意味です。

**関連**：②2カラムで足りるなら、列が少なく読みやすい②を選びます。

### ④ マスター＋ディテール

**アスキー図**
```text
┌──────────────┐
│ 一覧 │ 選んだ詳細 │
│      │           │
└──────────────┘
```

**ひとことで言うと**
左の一覧（マスター）で選ぶと、右の詳細（ディテール）が切り替わる骨格です。

**なぜこの形が生まれたか**
項目を次々に見比べるたび、一覧へ戻る手間をなくすためです。
メールアプリの件名一覧と本文の関係を思い浮かべると理解できます。

**向いている場面**
- 人物名鑑、メール、連絡先、ファイル管理
- 同じ種類の項目を続けて比較する画面

**向かない場面**
- 1項目をじっくり読む長文記事。左の一覧が本文幅を奪います。
- 狭い画面。2面を保つと両方が読めないため、縦積みか別画面にします。

**初心者がやりがちな失敗**
- 詳細データをJSだけに書く → JS停止時に情報が消える → HTMLへ全件を書き、JSは表示だけ切り替えます。
- 選択が見た目だけ → 読み上げ利用者に伝わらない → `aria-current`で現在項目を示します。

**実装の核心**
```css
.master-detail { display: grid; grid-template-columns: minmax(12rem, 30%) 1fr; }
```
`minmax()`は最小幅と最大幅をまとめて決める関数です。

**関連**：②2カラムは補助情報を添える型、④は選択によって右側が変わる型です。

### ⑤ ダッシュボード

**アスキー図**
```text
┌────┬────────┐
│KPI │ chart  │
├────┼───┬────┤
│list│ A │ B  │
└────┴───┴────┘
```

**ひとことで言うと**
数値、グラフ、一覧など大小のタイルを敷き詰め、全体の状態を見渡す骨格です。

**なぜこの形が生まれたか**
分析画面では順番に読むより、異常や変化を一目で探すことが重要だからです。
情報の重要度を面積や位置で示せます。

**向いている場面**
- 売上や利用状況を示す管理画面、KPI（重要な達成度を表す数値）の表示
- 複数の状態を同時監視する画面

**向かない場面**
- 記事や物語。読む順番が曖昧になります。
- 表示する数値が少ないページ。大げさな空箱が増えます。

**初心者がやりがちな失敗**
- すべて同じ大きさにする → 重要度が伝わらない → 最重要の指標だけ広い領域を与えます。
- スマホでもタイルを詰める → 文字が読めない → 狭い画面では1列にします。

**実装の核心**
```css
.dashboard { display: grid; grid-template-columns: repeat(12, 1fr); }
```
12分割の方眼紙を作り、各タイルが何マス使うかを決めます。

**関連**：⑬カードグリッドは同種の項目一覧、⑤は異なる種類の情報を同時表示します。

## 4. 層2：ナビゲーションのパターン

### ⑥ ヘッダーナビ＋ハンバーガー

**アスキー図**
```text
広い画面: [LOGO] [A B C]
狭い画面: [LOGO] [☰ MENU]
```

**ひとことで言うと**
画面上部にメニューを並べ、狭い画面では開閉ボタンへ畳む案内です。

**なぜこの形が生まれたか**
利用者はメニューが上にあると予想します。
期待に沿えば、説明がなくても移動方法を見つけられます。

**向いている場面**
- メニューが7個以下のWebサイト。迷ったらこの型を選びます。
- 1カラム、2カラムなど、どの骨格にも重ねられます。

**向かない場面**
- 項目が8個以上の大規模サービス。折り返しや長いメニューになるため⑦を検討します。
- スマートフォン内で頻繁に画面を切り替えるサービス。⑨の方が押しやすいです。

**初心者がやりがちな失敗**
- `☰`だけを置く → 意味が分からない人がいる → `MENU`という文字も添えます。
- 固定ヘッダーが移動先見出しを隠す → 上端へ重なる → `scroll-padding-top`を指定します。

**実装の核心**
```css
header { position: sticky; top: 0; }
.header-inner { display: flex; justify-content: space-between; }
```
`sticky`は、指定位置まで来ると画面に貼り付いて付いてくる配置です。

**関連**：⑦は項目が多いアプリ向け、⑧はスマホで一時的に出す面です。

### ⑦ 折りたたみサイドパネル

**アスキー図**
```text
開: [ナビ 240px][本文]
閉: [印 56px][本文   ]
```

**ひとことで言うと**
左のメニューを必要なときだけ広げ、不要なときは細く畳む案内です。

**なぜこの形が生まれたか**
項目数の多いアプリでは常設ナビが必要ですが、作業領域も広く使いたいからです。

**向いている場面**
- 管理画面、ダッシュボード、項目数の多いナビゲーション

**向かない場面**
- 数ページしかないサイト。開閉という操作の手間が利点を上回ります。

**初心者がやりがちな失敗**
- 閉じたアイコンの意味が不明 → 文字が消えたため → `title`などで名前を確認できるようにします。
- `div onclick`を使う → キーボードで押せない → 標準で操作できる`button`を使います。
- JSで幅を直接変える → 見た目がCSSとJSへ分散 → JSは`data-open`だけを変えます。

**実装の核心**
```css
aside[data-open="true"] { width: 240px; }
aside[data-open="false"] { width: 56px; }
```
状態はJS、見た目はCSSという役割分担にすると、幅の変更場所が1か所になります。

**関連**：⑧ドロワーは閉じたときに画面外へ完全に隠れます。

### ⑧ ドロワー

**アスキー図**
```text
閉: [本文       ]  ← パネルは画面外
開: [メニュー][暗い覆い]
```

**ひとことで言うと**
画面外から横に滑り込む、一時的なメニューや操作面です。

**なぜこの形が生まれたか**
狭い画面で本文の幅を保ちながら、多数の項目を必要時だけ見せるためです。

**向いている場面**
- スマートフォンのメニュー、商品絞り込み、買い物カート

**向かない場面**
- 常に見ながら操作する目次。閉じるたびに内容を忘れます。

**初心者がやりがちな失敗**
- 背後も押せる → 操作対象が曖昧 → オーバーレイ（背後を覆う半透明の面）を置きます。
- Escで閉じられない → キーボード利用者が抜けられない → Escと閉じるボタンを用意します。

**実装の核心**
```css
.drawer { transform: translateX(-100%); }
.drawer.is-open { transform: translateX(0); }
```
`transform`は位置や回転を見た目上変える指定で、滑らかな移動に向きます。

**関連**：⑦は閉じても56pxを残し、⑧は画面外へ隠れます。

### ⑨ ボトムナビ

**アスキー図**
```text
┌──────────┐
│   本文   │
├──────────┤
│ A  B  C  │
└──────────┘
```

**ひとことで言うと**
スマートフォン画面の下端に固定する主要メニューです。

**なぜこの形が生まれたか**
片手で持ったとき、親指が画面下部へ届きやすいからです。

**向いている場面**
- スマートフォン主体で、主要機能が3〜5個のサービス

**向かない場面**
- 長い説明サイトや項目が6個以上のサイト。本文を覆い、窮屈になります。

**初心者がやりがちな失敗**
- 本文末尾が隠れる → 固定面の高さを考慮していない → 本文下に同じ高さ以上の余白を取ります。
- アイコンだけにする → 意味が伝わらない → 短いラベルを添えます。

**実装の核心**
```css
.bottom-nav { position: fixed; inset: auto 0 0; }
```
`inset`は上下左右の位置指定をまとめる書き方です。

**関連**：⑥はサイト案内、⑨はアプリの主要機能切り替えに向きます。

### ⑩ タブ／アコーディオン

**アスキー図**
```text
タブ: [概要][仕様][料金] → 1面を切替
折畳: [質問 ▼]          → 直下を開閉
```

**ひとことで言うと**
タブは同じ場所の内容を切り替え、アコーディオンは見出しの下を開閉します。

**なぜこの形が生まれたか**
関連情報を小さな領域へ整理し、必要な部分だけ見せるためです。

**向いている場面**
- タブは設定画面や同格の情報、アコーディオンはFAQや詳細スペック

**向かない場面**
- すべて順番に読む必要がある内容。隠すと存在に気づかれません。

**初心者がやりがちな失敗**
- タブとリンクの見た目が同じ → ページ移動か切替か不明 → 選択中の状態を明示します。
- 重要情報を初期状態で隠す → 読まれない → 重要情報は常に表示します。

**実装の核心**
```html
<details><summary>質問</summary><p>回答</p></details>
```
単純な開閉ならHTML標準を使うと、キーボード操作を自作せずに済みます。

**関連**：⑧は画面全体に重なる面、⑩は本文内の小さな領域です。

### ⑪ パンくずリスト

**アスキー図**
```text
ホーム > 展示室 > 人物
```

**ひとことで言うと**
現在位置までの階層を、上位から順に示す案内です。

**なぜこの形が生まれたか**
検索結果から深いページへ直接来ても、サイト内の居場所と戻り道を分かるようにするためです。

**向いている場面**
- 商品カテゴリや資料サイトなど、階層が3段以上あるサイト

**向かない場面**
- 5ページ程度で階層が浅いサイト。ヘッダーナビと情報が重複します。

**初心者がやりがちな失敗**
- 見た目だけ`>`で並べる → 構造が伝わらない → `nav`と順序付きリストを使います。
- 現在ページもリンクにする → 同じ場所へ移動するだけ → 最後は文字で示します。

**実装の核心**
```html
<nav aria-label="パンくず"><ol>...</ol></nav>
```
`aria-label`は、読み上げ時に複数の案内を区別する名前です。

**関連**：⑥は主要ページへの移動、⑪は現在地から上の階層への移動です。

## 5. 層3：中身の並べ方のパターン

### ⑫ ヒーロー

**アスキー図**
```text
┌────────────────┐
│ 大見出し・要約・主要ボタン │
└────────────────┘
```

**ひとことで言うと**
ページ冒頭の広い領域で、最重要メッセージと次の行動を示します。

**なぜこの形が生まれたか**
訪問直後の数秒で「何のページか」「次に何をするか」を伝えるためです。

**向いている場面**
- サービス紹介LP、施設トップ、キャンペーン

**向かない場面**
- 毎日使う管理画面。大きな領域が作業を遠ざけます。

**初心者がやりがちな失敗**
- 画像を主役にする → 目的が伝わらない → 見出しと主要ボタンを先に決めます。
- 文字と背景の明暗が近い → 読めない → 暗い覆いなどで十分な差を作ります。

**実装の核心**
```css
.hero h1 { font-size: clamp(2rem, 6vw, 5rem); }
```
`clamp()`は最小値、画面に応じた値、最大値の順で文字サイズを制限します。

**関連**：⑮スプリットは画像と説明を同じ重さで並べます。

### ⑬ カードグリッド

**アスキー図**
```text
[項目][項目][項目]
[項目][項目][項目]
```

**ひとことで言うと**
同じ種類の項目を箱に分け、格子状に一覧表示します。

**なぜこの形が生まれたか**
各項目の情報構造をそろえ、斜め読みと比較をしやすくするためです。

**向いている場面**
- 商品、作品、記事、展示室の一覧

**向かない場面**
- 1本の長文や、順番を飛ばしてはいけない手順

**初心者がやりがちな失敗**
- カードごとに項目順が違う → 比較できない → 見出し、補足、説明の順を統一します。
- 固定列数にする → 狭い画面ではみ出す → 自動で列数を変えます。

**実装の核心**
```css
.cards { display: grid; grid-template-columns: repeat(auto-fill, minmax(220px, 1fr)); }
```
「220pxを下限に、入るだけ列を作り、余りを均等配分する」と読みます。

**関連**：⑤ダッシュボードは異種情報、⑬は同種項目を並べます。

### ⑭ マガジン／雑誌型

**アスキー図**
```text
┌────────┬───┐
│ 大記事 │小 │
├────┬───┴───┤
│ 中 │  中   │
└────┴───────┘
```

**ひとことで言うと**
記事の箱を大小不揃いにし、重要度の差を見せる並べ方です。

**なぜこの形が生まれたか**
ニュースの価値は同じではないため、面積と位置で読む優先順位を伝えます。

**向いている場面**
- ニュースサイト、編集されたメディアのトップ

**向かない場面**
- 同格の商品一覧。大きさの差が品質差だと誤解されます。

**初心者がやりがちな失敗**
- 見た目だけランダムにする → 読む順が不明 → 最重要記事を1つ決めてから配置します。
- HTML順を無視する → 読み上げ順が崩れる → 意味の順にHTMLを書きます。

**実装の核心**
```css
.featured { grid-column: span 2; grid-row: span 2; }
```
重要な記事だけ方眼紙の複数マスを使います。

**関連**：⑬は均等、⑭は編集者が意図的に強弱を付けます。

### ⑮ スプリットスクリーン

**アスキー図**
```text
┌────────┬────────┐
│ 画像・図 │ 説明文  │
└────────┴────────┘
```

**ひとことで言うと**
画面をほぼ半分に分け、図と文章など2つを同時に見せます。

**なぜこの形が生まれたか**
説明対象を見失わず、対応する文章を読めるようにするためです。

**向いている場面**
- 地図と地点解説、商品画像と説明、手本と手順

**向かない場面**
- 片側に十分な内容がないページ。空白が大きくなります。

**初心者がやりがちな失敗**
- スマホでも横並び → 両方が小さすぎる → 狭い画面は縦積みにします。
- 両側を固定する → 内容がスクロールできない → 固定する側を1つに絞ります。

**実装の核心**
```css
.split { display: grid; grid-template-columns: 55% 45%; }
```
左右の関係が二次元なのでGridが読みやすい選択です。

**関連**：②は本文と補助、⑮は2つの内容が同じ目的を支えます。

### ⑯ タイムライン

**アスキー図**
```text
● 1887 出来事
│
● 1890 出来事
```

**ひとことで言うと**
時系列の出来事を1本の線に沿って並べます。

**なぜこの形が生まれたか**
前後関係と時間の流れを、文章だけでなく位置でも伝えるためです。

**向いている場面**
- 刊行史、沿革、更新履歴

**向かない場面**
- 時間順に意味がない一覧。線が誤った関係を示します。

**初心者がやりがちな失敗**
- `div`だけで作る → 順序の意味が構造に残らない → 順序付きリスト`ol`を使います。
- 年の間隔をすべて同じにする → 長い空白期間が伝わらない → 区切りや余白で差を示します。

**実装の核心**
```css
.timeline::before { content: ""; position: absolute; inline-size: 1px; }
```
疑似要素はHTMLに文章を増やさず、線などの装飾を作るCSSの部品です。

**関連**：⑰は未来の手順、⑯は過去の出来事を示すことが多い型です。

### ⑰ ステッパー／ウィザード

**アスキー図**
```text
[1 入力] → [2 確認] → [3 完了]
```

**ひとことで言うと**
長い作業を複数段階へ分け、現在の段階と残りを示します。

**なぜこの形が生まれたか**
一度に大量の入力を見せず、完了までの見通しを与えるためです。

**向いている場面**
- 申込フォーム、購入手続き、初期設定

**向かない場面**
- 数項目だけの短い入力。画面移動が余計な手間になります。

**初心者がやりがちな失敗**
- 戻ると入力が消える → 状態を保持していない → 前後移動しても値を残します。
- 全段階数を隠す → 終わりが見えない → 「2/3」のように示します。

**実装の核心**
```html
<ol aria-label="申込の進行状況">...</ol>
```
順序に意味があるため`ol`を使い、現在段階は`aria-current="step"`で示します。

**関連**：⑩タブは自由な切替、⑰は決められた順番の作業です。

### ⑱ スティッキー・スクロールテリング

**アスキー図**
```text
┌──────┬────────┐
│固定図│流れる説明1│
│      │流れる説明2│
└──────┴────────┘
```

**ひとことで言うと**
図を画面に留めたまま文章をスクロールし、説明に応じて図の注目箇所を変えます。

**なぜこの形が生まれたか**
読者が図と説明を往復せず、変化の過程を追えるようにするためです。

**向いている場面**
- データ可視化、地図解説、複雑な仕組みの長い解説

**向かない場面**
- 短い記事や、図がなくても理解できる内容。実装負担が効果を上回ります。

**初心者がやりがちな失敗**
- スクロールイベントを直接監視する → 処理が何度も走る → `IntersectionObserver`を使います。
- 動きがないと読めない → JS停止時に情報が欠ける → HTMLに全説明を残します。

**実装の核心**
```css
.visual { position: sticky; top: var(--header-h); }
```
`IntersectionObserver`は、要素が画面へ入ったかをブラウザに効率よく知らせてもらう仕組みです。

**関連**：⑮は静的な左右配置、⑱はスクロールに応じた対応を加えた発展形です。

## 6. 選び方のフローチャート

```text
読ませることが主目的？
├─ YES → 常に見せたい目次や操作がある？
│         ├─ NO  → 【1カラム】
│         └─ YES → 【2カラム】
└─ NO  → 一覧から選んで詳細を見る動きが中心？
          ├─ YES → 【マスター＋ディテール】
          └─ NO  → 数値や異なるパネルを同時に見る？
                    ├─ YES → 【ダッシュボード】
                    └─ NO  → 【1カラム＋ヒーロー】
```

骨格を選んだ後、メニューが7個以下ならヘッダーナビを選びます。
8個以上で常時使うなら折りたたみサイド、スマホで一時的に使うならドロワーを検討します。
中身は、同種一覧ならカード、時間順ならタイムライン、図と説明ならスプリットを選びます。
迷ったら列と操作が少ない方を選び、必要が確認できてから増やします。

## 7. レイアウトを支えるCSSの3つの道具

| 道具 | ひとことで | 使う場面 | 覚え方 |
|---|---|---|---|
| 通常フロー | ブロック要素が上から下に積まれる初期動作 | 1カラム、文章 | デフォルトで十分なら何も書かない |
| Flexbox | 一列に並べて余りを配り合う | ヘッダー、2カラム、ボタン | 1本の線に並べる |
| Grid | 行と列の格子に配置する | 3カラム、カード、管理画面 | 方眼紙に置く |

### 通常フロー

通常フローは、特別なレイアウト指定をしないときのブラウザの並べ方です。
`header`、`main`、`footer`などのブロック要素は、初めから上から下へ積まれます。
1カラムなのにFlexboxを使うと、不要な指定が増え、後から読む人を迷わせます。
パターン01は最大幅と中央寄せだけを書き、初期動作を生かしています。

### Flexbox

Flexboxは横または縦という1方向に要素を並べ、空き幅を分けるのが得意です。
ヘッダーのロゴとナビを左右へ振る、本文とサイドバーを並べる用途に合います。
`display: flex`を書いた要素が親、その直下が並べられる子です。
子の中身がはみ出すときは、本文側の`min-width: 0`を確認します。

### Grid

Gridは縦横の両方を扱う方眼紙です。
3カラムや、行が増えるカード一覧のように列の関係を明示したいときに使います。
`repeat(auto-fill, minmax(220px, 1fr))`は、
「220pxを下限として、入るだけの列を自動で作り、余りは均等に分配する」と読みます。
メディアクエリ（画面幅などでCSSを切り替える仕組み）なしでも列数が変わります。

迷ったときは、1方向に並べたいならFlexbox、縦横どちらも制御したいならGridです。
2カラムはどちらでも作れます。
本教材はパターン02をFlexbox、パターン04をGridにし、多カラムを両方で書き比べます。

## 8. ベイカー街資料館での実際の選択と、その理由

### エントランス

選んだ型は「1カラム＋ヘッダーナビ＋ヒーロー＋カードグリッド」です。
目的は資料館の全体像を伝え、4つの入口から行き先を選んでもらうことです。
2カラムも検討できますが、常に見せる補助情報がないので捨てました。
実装上の難しさは、ヒーローを大きくしても次の入口が存在すると分かる高さにすることです。

### 人物名鑑

選んだ型は「マスター＋ディテール＋ヘッダーナビ」です。
9人の一覧から選び、詳細を続けて見比べる動きに合います。
1カラムも検討しましたが、人物を変えるたび一覧へ長く戻るため捨てました。
難しさは、狭い画面では一覧と詳細を同時表示できず、縦積みの移動を補う必要があることです。

### 年表

選んだ型は「1カラム＋ヘッダーナビ＋タイムライン」です。
時系列は縦1本で読むと前後関係が最も明確です。
聖杯も検討しましたが、左右へ置く情報がなく、本文を狭めるため捨てました。
難しさは、年と年の空きを表しつつ、ページを不必要に長くしないことです。

### 作品総覧

選んだ型は「2カラム＋ヘッダーナビ＋カードグリッド」です。
絞り込みを触りながら9冊を見比べるため、操作と結果の同時表示に価値があります。
1カラムも検討しましたが、絞り込みへ戻る手間が増えるため広い画面では捨てました。
難しさは、狭い画面で絞り込みを上、結果を下へ自然に並べ直すことです。

### ロンドン地図

選んだ型は「スティッキー・スプリット＋ヘッダーナビ」です。
地図を見失わず、6か所の解説との対応を追えるからです。
通常の2カラムも検討しましたが、地図まで一緒に流れると比較しにくいため捨てました。
難しさは、固定が使いにくい狭い画面で解説リストを主役へ切り替えることです。

### 採用しなかった型

聖杯は右カラムへ置くほどの情報がなく、空の列が本文を狭めるため採用しません。
折りたたみサイドパネルは全5ページでは、開閉の操作コストが得られる幅より大きいため採用しません。
型を知る目的は全部使うことではなく、不要な型を理由付きで捨てることです。

## 9. 用語集

- アクセシビリティ：障害や操作方法にかかわらず情報や機能を利用できる度合い。
- カラム：ページを分ける縦の列。
- コンテナ：複数の要素をまとめ、幅や配置の基準にする親要素。
- セマンティックHTML：見た目ではなく意味に合うタグを選ぶ書き方。
- 通常フロー：指定しなくても要素が文書順に並ぶブラウザの初期動作。
- Flexbox：要素を1方向に並べ、空き幅を分けるCSSの仕組み。
- Grid：行と列の方眼紙へ要素を置くCSSの仕組み。
- レスポンシブ：画面幅や入力方法に応じて使いやすい配置へ変える設計。
- ブレークポイント：配置を切り替える境目の画面幅。
- メディアクエリ：画面幅などの条件に応じてCSSを適用する仕組み。
- `ch`：数字の0のおよその字幅を1とするCSS単位。
- `fr`：Grid内の余った空間を分けるCSS単位。
- `min-width: 0`：Flexboxの子が中身より小さく縮めるよう、初期の最小幅を解除する指定。
- `position: sticky`：指定位置まで来ると、画面へ貼り付いて付いてくる配置。
- `transform`：要素の位置、拡大縮小、回転を見た目上変える指定。
- `transition`：状態が変わる途中を滑らかにつなぐ指定。
- 疑似要素：`::before`など、HTMLを増やさず装飾用の箱を作る仕組み。
- `aria-expanded`：開閉部品が現在開いているかを支援技術へ伝える属性。
- DOM：ブラウザがHTMLを要素の木構造として扱う表現。
- オーバーレイ：操作中の面を明確にするため、背後を覆う半透明の層。
