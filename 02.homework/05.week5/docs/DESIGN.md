# かけら デザイン定義書

version 1.0 / 2026-07-31

本書は見た目と文言を定める。機能の定義は REQUIREMENTS.md に従う。

---

## 1. コンセプト

> **拾って、とっておく。**

価値を決めずに、とっておく場所。

玄関の小皿を想像するとよい。石ころ、切符、なくした鍵。そこに置かれるものに価値の審査はない。あとで見返したときに、何かが分かるかもしれないし、分からないかもしれない。**審査がないから置ける。**

このアプリが与えるべき感情は、達成感でも高揚でもない。

> **「こんなことを書いてもいいんだ」**

これだけである。すべての判断をここから導く。

### 設計原則

| 原則 | 意味 | 具体化 |
|---|---|---|
| 審査しない | 数値・比率・連続日数を見せない | 画面上の数字は日付だけ。他に数値表示が存在しない |
| 空欄も一片 | 書けなかった日を失敗として描かない | 未記入日も記入日と同じ形・同じ大きさ |
| 軽い器 | 重々しくしない。開くのに気合いが要らない見た目 | 淡い地色と面のわずかな沈み込み、広い余白で構造を出す。線は入力下線・ヘッダー下・副ボタンの 1 px の罫に限る |
| 器は黙る | UI が記録より前に出ない | カードを枠で囲まず、欠けた形も要所だけに絞る。UI はゴシック小サイズ、記録本文だけ明朝で最大 |
| 祝わない | 保存を達成として演出しない | 保存後は短い一文のみ。跳ねない、光らない、鳴らない |

## 2. 色

### 方針

淡色（ペールトーン）を地とし、**濃い色は文字とアクセントにだけ使う**。

ただし全面をパステルにはしない。淡い色ばかりの画面は、優しさではなく**幼さ・安っぽさ**として読まれ、書いた内容まで軽く扱われた感じになる。淡い地に、しっかり濃い墨と藍を置く。緊張感は色の濃さではなく、**余白と線の細さ**で作る。

### トークン

| トークン | 色名 | 値 | 用途 |
|---|---|---|---|
| `--color-sushi` | 地 | `#eef1f1` | 画面全体の地 |
| `--color-men` | 面 | `#fafcfc` | カード・入力欄。地よりわずかに明るい面 |
| `--color-kei` | 罫 | `#dde3e3` | ヘッダー下と入力欄の下線 |
| `--color-sumi` | 本文 | `#333c40` | 本文 |
| `--color-nibi` | 補助 | `#616c74` | ラベル・補助文字 |
| `--color-ai` | 藍 | `#33566e` | 主アクセント。フォーカス・現在地・主ボタン |
| `--color-seiji` | 青磁 | `#3e6b63` | 「ひとつ」（月の外出）専用 |
| `--color-kin` | 金 | `#85631f` | **開放時のみ** |
| `--color-ai-usu` | 淡藍 | `#e6ecef` | 藍系の面（保存後カードなど） |
| `--color-seiji-usu` | 淡青磁 | `#e5eceb` | 「ひとつ」の面 |

### コントラスト実測

| 色 | ライト | ダーク | AA (4.5:1) |
|---|---|---|---|
| 本文 | 9.93 | 10.96 | ✓ |
| 補助 | 4.73 | 5.22 | ✓ |
| 藍 | 6.85 | 7.56 | ✓ |
| 青磁 | 5.30 | 5.85 | ✓ |
| 金 | 4.86 | 5.36 | ✓ |
| 白 on 藍 | 7.56 | — | ✓ |

### 三つの色の役割分担

- **藍**：日々ふれる色。フォーカスリング、主ボタン、日々の確定操作
- **青磁**：月に一度だけ関わる色。「ひとつ」の画面と、外出した日に付く印
- **金**：60日後の開放でしか現れない。**それまで一度もどの画面にも出さない**

金を他の用途（強調・リンク・警告）へ流用してはならない。一度でも他所で使えば、開放の意味が消える。

### 使わない色

- **赤系** — 未記入・欠損・警告に使わない。この製品に「失敗」の状態は存在しない
- **緑系（明るい成功色）** — 達成の表現に使わない
- **グラデーション** — 階層は単色の明度差だけで表す

### ダークモード

`prefers-color-scheme: dark` で切り替える。**黒地にはしない。輝度を落とした紙として扱う。**

| 面 | `#fafcfc` | `#2f3537` |
| 罫 | `#dde3e3` | `#3b4244` |
| 本文 | `#333c40` | `#e4e9ea` |
| 補助 | `#616c74` | `#9ea9ae` |
| 藍 | `#33566e` | `#94b7d0` |
| 青磁 | `#3e6b63` | `#8db9ae` |
| 金 | `#85631f` | `#d3ae72` |
| 淡藍 | `#e6ecef` | `#2c383f` |
| 淡青磁 | `#e5eceb` | `#2b3a37` |

ダークでも純黒（`#000`）は使わない。地は炭色の紙であり、光の当たっていない紙という扱いにする。

## 3. 書体

| 役割 | 書体 | 用途 |
|---|---|---|
| 表示 | Zen Old Mincho | ロゴタイプ、**記録本文**、日付 |
| 実用 | Zen Kaku Gothic New | ラベル、ボタン、説明文 |

### 割り当ての理由

**書いた本人の言葉だけが明朝になる。** アプリの都合（ラベル、ボタン、注意書き）はすべてゴシックで、記録本文と明確に別の層に置く。ユーザーの一行が、UI の文字列と混ざらないようにするため。

### プレースホルダ

プレースホルダは全画面で同一の扱いとし、ゴシック・`text-ui`・鈍色・不透明度 60% とする。入力済みの文字（明朝または `text-base`・墨）とは、書体と濃さの両方で区別できること。濃さを入力欄ごとに変えない。

### 文字サイズ

| 用途 | base（〜767 px） | `md` 以上 | 行送り |
|---|---|---|---|
| ロゴタイプ | 26 px（字間 0.32em） | 30 px | 1.2 |
| **記録本文（明朝）** | **17 px** | **18 px** | 1.9 |
| 入力欄（済・人） | 16 px | 16 px | 1.6 |
| ラベル・日付・説明 | 13 px | 14 px | 1.7 |
| 注記 | 12 px | 12 px | 1.7 |

- 見出しより記録本文のほうが大きい。**画面上で最も大きな文字は、常にユーザーが書いた一行である**
- 入力欄は 16 px を下回らない（iOS の自動ズーム防止／NFR-4.3）
- 太字は使わない。強さは色と余白で作る
- 拡大は `md` で1段階のみ。それ以上は広い画面でも上げない（NFR-4.8）

## 4. 署名要素：欠けた正方形

```
┌──────────┐
│          │
│         ╲│
└────────╲ ┘
```

右下が落ちた矩形。器全体へ繰り返す装飾ではなく、名前「かけら」を示す署名として要所だけに用いる。

```
clip-path: polygon(0 0, 100% 0, 100% calc(100% - 14px), calc(100% - 14px) 100%, 0 100%);
```

| 項目 | 仕様 |
|---|---|
| 適用範囲 | アプリマーク、面を持つ要素、主ボタン、小さい欠けを持つ副ボタン、ファビコン |
| 欠けの寸法 | 14 px（小型要素は 9 px） |
| 角丸 | 使わない |
| 淡色地での視認 | アプリマーク・保存後カード・主ボタンは面と地の明度差で形を出し、副ボタンだけは 1 px の罫を使う |
| 影 | 使わない。浮かせず、置いてあるように見せる |

**意図**：名前「かけら」を署名として実装する。記入した日も「なし」の日も同じ欠けた形で並ぶ。形が同一であることが「空欄も一片」の視覚的な宣言になる。

## 4.1 部品

画面をまたいで使う部品は、以下の定義に揃える。用途ごとに別の書式を足さない。

### 入力欄

| 階層 | 用途 | 書体・サイズ | 下線 | フォーカス |
|---|---|---|---|---|
| 主 | 心が動いたこと／今月の目的 | 明朝・`text-record`（`md` 以上 `text-record-md`） | `border-b-2 border-nibi` | `focus:border-ai`（ひとつ画面は `focus:border-seiji`） |
| 副 | 済／人 | ゴシック・`text-base`（16px を下回らない） | `border-b border-kei` | `focus:border-ai` |

- 上下左右の枠線を持たない。下線だけで書く場所を示す
- プレースホルダは全画面共通で `placeholder:font-gothic placeholder:text-ui placeholder:text-nibi placeholder:opacity-60`
- 背景は `bg-transparent`

### 面

**面を持つ要素は、例外なく欠けた正方形の形を持つ。**

| 面の大きさ | 形 |
|---|---|
| 大きい面（記録カード、初回説明、確認パネル） | `shard`（欠け 14px） |
| 小さい面（かけら一覧の各カード、目的の面） | `shard-sm`（欠け 9px） |

角丸は使わない。影は使わない。面を持たない部品（下線だけの移動導線）には形を与えない。

| 面 | 使う場所 |
|---|---|
| `bg-ai-usu`（淡藍） | **本人の一行が置かれた面**。今日の記録カード |
| `bg-seiji-usu`（淡青磁） | **今月の目的が置かれた面**。ひとつの目的 |
| `bg-men`（面） | 置かれた紙。かけらの一覧カード、初回説明、確認パネル |
| `bg-sushi`（地） | 背景のみ。部品の面に使わない |
| `bg-ai` / `bg-sumi` | 主ボタンとその押下時のみ |

### 見出し

| 種類 | 書式 |
|---|---|
| 画面見出し | 明朝・`text-record`・墨 |
| 日付（今日の主見出し） | 明朝・`text-ui`・`tracking-date`・鈍色 |
| 節見出し | ゴシック・`text-ui`・藍 |

この3つ以外の見出し書式を作らない。

### フォーカス

すべての操作可能な要素に `focus-visible:outline-2 focus-visible:outline-offset-2` と、対応する色（藍／ひとつ画面は青磁／開放の報せは金）を付ける。**`outline-offset` の有無を要素ごとに変えない。** 内包する非表示のフォーム部品へフォーカスを委ねる要素では、同じ指定を `focus-within` で外側に表す。

### 状態メッセージ

| 種類 | 扱い |
|---|---|
| 誤り（一行だけ書くか、「なし」を押してください） | ゴシック・`text-ui`・鈍色。**赤や警告色を使わない** |
| 復元の可否（復元しました／控えを読めませんでした） | 同上 |
| 完了（記録を置きました 等） | 画面に出さず、`role="status"` の領域にのみ入れる |

### 記号

| 記号 | 意味 |
|---|---|
| `◇` | 決めてある外出 |
| `◆` | 行った直後の反応（その場限り） |
| `＋` / `−` | 開閉 |
| `←` | 戻る |
| `—` | 未記入の日 |

これ以外の記号を増やさない。絵文字を使わない。

### ボタン

**判定基準は、押すと何かが確定するのか、移動するだけなのか。** 操作の頻度や文言の長さではなく、押した結果で階層を決める。

| 階層 | 見た目 | 対象 |
|---|---|---|
| **主** | 藍の面（`bg-ai`）・`text-men`・欠けた正方形（`shard`）・幅いっぱい・高さ `min-h-button`。**1画面に1つだけ** | 記録する／はじめる |
| **副** | 面を持たない。`border border-kei` の 1 px の罫で囲み、小さい欠け（`shard-sm`）。文字は藍（`text-ai`）、「ひとつ」に関するものは青磁（`text-seiji`）。左右の余白は 20 px（`px-5`）、高さ `min-h-touch` | なし／行った／決める／書き換える／控えを取る／控えから復元する／控えを取ってから進む系の確認ボタン（次へ・戻る・使うのをやめる の確認2段階のボタン） |
| **移動** | 下線のみ（`underline underline-offset-4 decoration-kei`）・鈍色（`text-nibi`）。枠も面も持たない | これまでを見る／今月のひとつ／← 今日／← かけら／書き直す／もう一度読む／はじめの言葉／このアプリについて |

- 「記録をテキストで書き出す」は、押すと書き出しが確定するため「副」とする
- 「使うのをやめる」（「このアプリについて」最下部の入口）は例外として、`text-note`・鈍色・下線のみとする。距離で止める設計のため、押しやすくしない
- 「＋ 済・人」／「− 済・人」は開閉トグルであり、確定でも移動でもない。表の外として、下線なし・鈍色・記号付きの現状を保つ
- タップ対象はすべて 44 px 以上とする（NFR-4.2）
- ホバーでは面の色だけを一段変える。フォーカスリングは通常は藍、「ひとつ」に関する操作は青磁とする

## 5. レイアウト

**全幅で1カラム。タブ（常時表示のナビゲーション）を置かない。** 画面構成と遷移は UX.md に従う。

### 5.1 今日（書く前）　〜639 px／基準

```
┌─────────────────────────┐
│ ◪ かけら                │  小型ヘッダー・左右余白 20px
├─────────────────────────┤
│ 7月31日                 │  ← 主見出し・明朝・鈍色
│                         │
│ 心が動いたこと           │  ← ゴシック・13px・鈍色
│ 腹が立った、いいな…      │  ← 入力は明朝・18px（画面最大）
│ ━━━━━━━━━━━━━━━━━━━━━   │  ← 通常は鈍色、フォーカス時は藍
│ なし              ＋ 済・人│  ← 面のない補助操作
│                         │
│ （トグルを開いた場合）    │
│ 済 ─────────────────    │
│ 人 ─────────────────    │
│                         │
│ ▉▉▉ 記録する ▉▉▉        │  ← その日の全入力の直後・藍・高さ 52px
│                         │
│                         │
│ これまでを見る  今月のひとつ│  ← 最下部。左右に振り分け、同じ書式
└─────────────────────────┘
```

- 「済」「人」は初期状態では表示しない。既にどちらかの値がある場合だけ開いた状態にする
- 「記録する」は常にその日に入力する全項目の下に置き、「済」「人」の開閉に合わせて上下する
- 起動時、入力欄にフォーカスを当てる。**日付・入力欄・「なし」・「記録する」が同時に見えること**
- 画面名（「今日」の語）を出さない。日付があれば足りる

### 5.2 今日（置いたあと）

その日の用は終わっている。要求を追加しない。

```
┌─────────────────────────┐
│ ◪ かけら                │
├─────────────────────────┤
│ 7月31日                 │
│          ↕ 12           │
│ ┌───────────────────╲   │  ← 欠けた正方形・淡藍の面
│ │ 町ブラ良いなと思った │   │  ← 明朝・18px
│ │ 済 歯医者の予約      │   │
│ └────────────────────┘   │
│          ↕ 8            │
│ 書き直す                │  ← カード外・左寄せ・鈍色・12px・下線のみ
│          ↕ 40           │
│                         │
│   蝉の声が、少しずつ…    │  ← 今日の一言・明朝・鈍色・中央
│          ↕ 56           │
│                         │
│ ─ 用がある日だけ、一行 ─  │
│ ◇ 中華そばを食べる ［行った］│  ← 登録済み・未実行のときのみ
│ 読み返せます             │  → かけら（開放日のみ・金）
│          ↕ 80           │
│                         │
│ これまでを見る  今月のひとつ│  ← 左右に振り分け、同じ書式
└─────────────────────────┘
```

条件と出し分けは UX.md 6章および REQUIREMENTS FR-3.11 に従う。**実行済みの月は何も出さない。**

### 5.3 広い画面（`sm` 〜 `xl`）

**カラムを増やさない。増えるのは余白だけ。**

```
      〜639            640〜767           768 px 〜
┌──────────────┐  ┌──────────────┐  ┌────────────────────┐
│ 全幅          │  │  最大 560px   │  │     最大 620px      │
│ 余白 20       │  │  余白 32・中央 │  │      中央寄せ       │
└──────────────┘  └──────────────┘  └────────────────────┘
```

`lg`・`xl` でも1カラムを保ち、複数の画面を同時に表示しない。広い画面で得るのは情報量ではなく、一行のまわりの静けさである。

### 5.4 このアプリについて

「かけら」画面の最下部から入る、静かな1枚。日々の画面には出さない。

```
┌─────────────────────────┐
│ ← かけら                │
│                         │
│ このアプリについて       │
│ 拾って、とっておく。      │
│                         │
│ はじめの言葉             │  ← FR-4.3 の再表示
│ 記録の保存先             │  ← どこに残るか（NFR-7.4）
│ ログインしている場所      │  ← P2-1.10。P1 では出さない
│ アプリロック             │  ← P2-1.11。既定は無効
│                         │
│ ─────────────────────   │
│ 使うのをやめる           │  ← 最下部。鈍色・小・下線のみ
└─────────────────────────┘
```

- 「使うのをやめる」は、他の項目と同じ大きさにしない。目に入るが、押しにくい位置と大きさに置く
- 赤字にしない。危険色は使わない（第2章「使わない色」）。**警告で止めるのではなく、距離で止める**

### 5.5 余白

7段階に固定する。中間値を足さない。

`8 / 12 / 20 / 28 / 40 / 56 / 80 px`

| 場面 | 値 |
|---|---|
| ラベルと主入力欄の間 | 8 |
| 入力欄どうし | 28 |
| 書く前の入力ブロックと「これまでを見る」の間 | 80 |
| 保存後の日付と記録カードの間 | 12 |
| 保存後カード内 | 横 28、縦 28 |
| 保存後の記録カードと「書き直す」の間 | 8 |
| 保存後の記録カードと「今日の一言」の間 | 40 |
| 保存後の「今日の一言」と月の一行の間 | 56 |
| 保存後の月の一行と「これまでを見る」の間 | 80 |
| 一覧カード内 | 横 20、縦 12 |
| 一覧のカード間 | 12 |
| セクション間 | 80 |
| ヘッダー上下 | 12 |

初回説明は、目的を最初に読ませ、「なぜ → 何を → いつ」の順に主従をつける。

| 要素 | 指定 |
|---|---|
| 見出し「拾って、とっておく。」 | 明朝。字間は通常（`tracking-logo` を使わない）。サイズは記録本文と同じ（`text-record-md`）。390 px で1行に収める |
| 目的の一文（何かに反応した瞬間だけが…） | 明朝・`text-record`・墨。この画面で最も強い要素にする |
| 行為の一文（一日に一行…） | ゴシック・`text-ui`・鈍色 |
| 時期の一文（読み返せるのは…） | ゴシック・`text-ui`・鈍色 |
| ［はじめる］ | 藍の主ボタン。欠けた正方形（`shard`）を当て、「記録する」と同じ扱いにする |

| 間 | 値 |
|---|---|
| 見出し → 目的の一文 | 40 |
| 目的の一文 → 行為の一文 | 28 |
| 行為の一文 → 時期の一文 | 12 |
| 時期の一文 → ［はじめる］ | 56 |
| カード内の上下余白 | 40 |

保存後カードは本文カラムの全幅を使い、内容に応じて伸びる。一行だけの記録に固定の最小高を持たせない。「書き直す」はカードの外側・直下に左端を揃えて置き、ゴシック 12 px・鈍色・下線のみとする。操作面や枠は付けず、タップ対象だけは 44 px 以上を保つ。カード全体を操作対象にしてもよい。一覧は未記入日にも同じ幅・最小高・書式を用いる。

区切りは線ではなく、この余白で示す。`md` 以上でも7段階の中から選び、画面高 500 px 未満では上下方向のみ段階を下げて圧縮する（NFR-4.5）。主要画面の末尾余白は安全領域に必要な分だけとし、短い内容を埋めるための最小高は設けない。

### 5.6 ビューポートに対する縦位置

| 状況 | 縦位置 |
|---|---|
| 内容がビューポートより短い | ヘッダーを除いた領域の中で、縦の中央よりやや上に置く。上下の余白比はおおよそ 4:5 とする |
| 内容がビューポートより長い | 中央寄せせず、通常どおり上から流す。縦位置のために内容を切らない |
| ソフトキーボード表示時 | `dvh` 系の単位で領域の縮小に追従し、入力中の欄を隠さない。縮小時は上詰めに戻してよい（NFR-4.6） |
| 画面高 500 px 未満 | 上下余白を圧縮し、入力欄と「記録する」を同時に見せる（NFR-4.5） |

ページ全体は `min-h-dvh` の縦方向 Flex とし、本文に残りの高さを渡す。短い内容はその残余領域で配置し、長い内容は本文の自然な高さでページを伸ばす。

## 6. 動き

| 場面 | 動き | 時間 |
|---|---|---|
| 画面切り替え | 不透明度のみ | 0.4s |
| 保存完了 | 記録カードが上から 8px 下りて納まる | 0.4s `cubic-bezier(.16,.84,.44,1)` |
| 「行った」 | 青磁の印が静かに現れる | 0.3s |
| 開放バナー | 金がゆっくり明滅する | 6s ループ |
| ホバー／押下 | 面の色が一段変わるのみ | 150ms |

拡大・回転・跳ね返り・紙吹雪・効果音は使わない。保存は達成ではなく、**置くこと**だから。

`prefers-reduced-motion: reduce` ですべて無効化する（NFR-5.3）。

## 7. 言葉

UI 文言も設計対象とする。

| 場面 | 採用 | 不採用 | 理由 |
|---|---|---|---|
| 初回説明への導線 | はじめの言葉 | はじめに読んだ説明 / はじめての説明 | 中身は説明ではない。時制も説明しない |
| 保存ボタン | 記録する | 保存 / 送信 | 行為の名で呼ぶ |
| 保存後 | （今日の一言。下記） | 記録しました！ / 続けてえらい | 祝わない |
| 未記入日 | `—` | 未記入 / 記録なし | 欠けを名指ししない |
| 入力例 | 腹が立った、いいなと思った、など | 感謝したこと / 学んだこと | 立派でない例を出す（FR-1.11） |
| 空入力時 | 一行だけ書くか、「なし」を押してください | エラー：入力必須です | 直し方を示す。謝らない |
| 開放前 | これより前は、二か月後に読み返せます | ロック中 / あと◯日 | 制限ではなく約束として書く |
| 開放時 | 読み返せます | おめでとうございます | 事実だけ |
| 記録なし | 今日のぶんから始まります | データがありません | 空の画面は誘いにする |
| やめる（入口） | 使うのをやめる | 削除 / データを消去 | 消す対象は記録ではなく、続けること |
| やめる（確認） | 先に控えを取れます | 本当によろしいですか？ | 引き返す道を先に示す |
| やめる（完了） | 消しました | 削除が完了しました | それ以上言わない |
| 登録のお願い | この一行を、次の端末にも残しますか | 会員登録して続きを楽しもう | 目的だけを言う |
| 登録の理由 | 端末を替えても消えないようにするためです | アカウントを作成すると便利です | 何のためかを具体に言う |
| ログイン | メールに送った鍵で入ります | ログインしてください | 動作を言う |
| ロック画面 | かけら | （記録の一部を表示） | 中身を見せない（P2-1.13） |
| 同期の失敗 | （何も出さない） | 同期に失敗しました | 次回送られるので、知らせる必要がない（P2-0.4） |
| ひとつ（未登録） | 今月のひとつを決めますか | 今月はまだ外出していません | 提案する。不足を指摘しない |
| ひとつ（説明） | 今月、行ってみる場所をひとつ。<br>行く途中で気になる場所を見つけたら、そちらに変えてもかまいません。 | 目標を達成しましょう | 達成を降ろす。理屈を説明しない。「捨てる」ではなく「変える」— 寄り道を許すことで、決めた場所への到達を目標にしない |
| 初回・一 | きれいだと思った。<br>腹が立った。 | どんな瞬間も、書かなければその日のうちに消えます | 説明しない。**瞬間そのものを置く**。二行だけ |
| 初回・二 | 消えてしまう前に、<br>一日に一行、拾っておく。 | 夜には、消えている。（別の一文として置く） | 理由を独立した文にしない。**行為の側に畳む**と一文減る |
| （置かない） | — | 二か月後、まだ動いていた自分がいる。 | 0.1 の言葉をそのまま持ち込まない。初めて読む人に通じない。二か月後のことはかけら画面で足りる（FR-4.9） |

初回説明は、機能の説明ではなく**その瞬間が消えるということ**を伝える場である。
説明的に書かない。短く切り、余白を多く取る。読んだ人が自分の一日を思い出し、それが失われることを感じ取れれば足りる。
**書き足す前に、削れる語を探す。** 指し直す語（「その一瞬は」）、自明な動作（「ひらくと」）、場所を指す語（「そこに」）、比喩の説明は落とす。

命令形の押し付け（「今日も書こう！」）、感嘆符、絵文字は用いない。

### 7.1 今日の一言

保存後に表示する一文（FR-8）。日付から決まり、書いた内容には触れない。

役割は、**その日が昨日とは違う日だったと示すこと**だけ。書いた人を評価しないまま、毎日ちがう画面を返すための装置である。

#### 執筆規則

| 規則 | 内容 |
|---|---|
| 1 | 二人称を使わない（「あなた」「きみ」を含めない） |
| 2 | 評価・称賛・励まし・助言・慰めを含まない |
| 3 | 命令形・勧誘形を使わない（「〜しよう」「〜してみて」を含めない） |
| 4 | 継続・日数・記録の量に触れない |
| 5 | 書かれた内容に触れない |
| 6 | 人の内面を describe しない。外の世界の観察に限る |
| 7 | 12〜24 字。句点を打たない |
| 8 | その日の暦（二十四節気・七十二候）の範囲内の事象に限る |
| 9 | 断定を弱める（「〜頃」「〜らしい」を活かす） |

#### 例

| 時期 | 一言 |
|---|---|
| 1月上旬 | 水たまりに薄い氷が張る頃 |
| 2月下旬 | 風の当たり方が、少しだけ変わる |
| 4月上旬 | 桜の下だけ、風が白い |
| 6月中旬 | 雨の音が、屋根ごとに違う |
| 7月下旬 | 蝉の声が少しずつ入れ替わる頃 |
| 8月上旬 | 夕立のあと、道の匂いが変わる |
| 9月中旬 | 日の入りが、先週より二分早い |
| 11月上旬 | 朝、屋根が白いことがある |
| 12月下旬 | 日が、いちばん短いあたり |

#### 表示

| 項目 | 仕様 |
|---|---|
| 位置 | 記録カードの下、中央寄せ |
| 書体 | 明朝 |
| 色 | 鈍色 |
| サイズ | 14 px（`md` 以上 15 px） |
| 余白 | カードから 40 px |
| 動き | カードが納まったあと 0.2 秒遅れて、不透明度のみで現れる |

その日のうちは何度開いても同じ一文が出る。翌日には消え、見返す手段は用意しない（FR-8.6）。

#### 執筆量

366 件。うるう日（2月29日）を含む。年をまたいで同じ日には同じ一文が出る。
これは不具合ではなく仕様であり、暦が毎年めぐるのと同じ扱いにする。

## 8. 実装の前提（Tailwind CSS）

本書のトークンは Tailwind CSS v4 を前提に定義している。**CSS フレームワークを自作しない。** スタイルはマークアップ側のユーティリティクラスで当て、独自のクラス体系を作らない。

### 8.0 何を Tailwind に任せ、何を書くか

「今日の一言」を表示するかどうかは保存操作直後だけの一時状態としてメモリ内で扱う。保存済みデータから復元しないため、再読み込み・起動・画面へ戻ったときには描画しない（FR-8.5）。

| 項目 | 担当 |
|---|---|
| 余白・配置・寸法・色・文字サイズ・状態変化 | **Tailwind のユーティリティ**（`px-5`、`bg-men`、`text-sumi`、`md:text-lg`、`hover:` など） |
| レスポンシブ | **Tailwind のブレークポイント**（`sm:` / `md:` / `lg:` / `xl:`） |
| トークンの定義 | `styles.css` の `@theme`。v4 ではこれが設定ファイルそのもの |
| 署名要素（欠けた正方形） | `@utility`。Tailwind の公式なカスタムユーティリティ機構 |
| ダークモードの値 | メディアクエリでトークンを差し替え（8.4） |
| `@font-face` | fontsource の定義からビルド時に生成し、`fonts.css` として分離する |

**上記以外に CSS を書かない。** `.card` `.btn` のような独自クラスを定義しない。

書き方の例。

```html
<article class="shard bg-men border border-kei px-5 py-4 md:px-6">
  <p class="font-mincho text-[13px] tracking-[0.22em] text-nibi">7月31日</p>
  <p class="mt-2 font-mincho text-record text-sumi">町ブラ良いなと思った</p>
</article>
```

見た目の情報はすべてクラスにある。この要素のための CSS を別ファイルに書き足すことはない。

### 8.1 取得と生成

| 項目 | 内容 |
|---|---|
| 取得方法 | npm で `devDependencies` に入れる。**CDN を使わない** |
| 生成 | Tailwind CLI でビルドし、生成済みの CSS を1ファイルだけ配信する |
| 出力 | 使われているクラスのみ。未使用のユーティリティを出力しない |
| 圧縮 | `--minify` |
| 設定ファイル | **`tailwind.config.js` を置かない。** v4 は CSS 側で設定するため、`styles.css` が設定を兼ねる |
| 目標サイズ | 生成 CSS は 20 KB 以内（NFR-1.1 の内訳） |

ブラウザ上でユーティリティを生成する方式（CDN 版）は使わない。実行時に第三者コードを読み込まない方針（NFR-6.7）と、初回転送量の目標（NFR-1.1）の両方に反するため。

### 8.2 トークンの置き方

第2〜3章の色・書体・寸法は、すべて `@theme` に定義する。

```css
@import "tailwindcss";

@source "./index.html";
@source "./app/**/*.js";

@theme {
  --color-sushi:  #f2ece9;   /* 素紙 */
  --color-men:    #fffdfc;   /* 面 */
  --color-sumi:   #3b3531;   /* 墨 */
  --color-ai:     #2f4e68;   /* 藍 */
  /* 以下、第2章の表のとおり */

  --font-mincho: "Zen Old Mincho", serif;
  --font-gothic: "Zen Kaku Gothic New", sans-serif;
}
```

`@source` で走査対象を明示し、そこに現れるクラスだけを出力する。

### 8.3 署名要素

欠けた正方形（第4章）は `@utility` として1か所に定義し、カード・ボタン・アプリマークで共有する。個別に `clip-path` を書かない。

```css
@utility shard    { clip-path: polygon(0 0, 100% 0, 100% calc(100% - 14px), calc(100% - 14px) 100%, 0 100%); }
@utility shard-sm { clip-path: polygon(0 0, 100% 0, 100% calc(100% - 9px),  calc(100% - 9px)  100%, 0 100%); }
```

### 8.4 ダークモード

`dark:` を各要素に付けて回らない。**`@media (prefers-color-scheme: dark)` の中でトークンの値だけを差し替える。**

```css
@media (prefers-color-scheme: dark) {
  :root {
    --color-sushi: #2a2725;
    --color-men:   #34302d;
    --color-sumi:  #eae3de;
    /* 第2章のダーク列のとおり */
  }
}
```

マークアップは1種類のまま、色だけが入れ替わる。

### 8.5 書いてはならないこと

| 禁止 | 理由 |
|---|---|
| CSS に色・寸法の値を直書きする | トークンを通らない変更が生まれる（NFR-8.2） |
| 任意値（`bg-[#f2ece9]` のような角括弧記法）で色を指定する | 同上 |
| **クラス名を JS の文字列連結で組み立てる**（`` `bg-${name}` ``） | 走査で拾えず、生成 CSS から消える。分岐は完全なクラス名を並べて書く |
| `!important`（`!` 接頭辞） | 打ち消しの連鎖が始まる |
| `dark:` を要素ごとに付ける | 8.4 の方針に反する |
| `.card` `.btn` などの独自クラスを定義する | 自作フレームワークになり、トークンとの対応が追えなくなる |
| `@apply` でユーティリティをまとめる | 上と同じ。共通化したくなったら、まずマークアップ側の重複を疑う |
| コンポーネントごとに CSS ファイルを増やす | スタイルの所在が2か所に分かれる |

### 8.6 書体の配信

Web フォントも CDN 依存を残さない。fontsource の `400.css` から `unicode-range` と `font-display: swap` を維持した `@font-face` をビルド時に生成し、参照される `woff2` サブセットだけを `web/dist/fonts/` へコピーして自己ホストする（NFR-1.6、NFR-9.5）。
必要なウェイトは 400 のみに絞る。日本語はサブセット分割して配信する。`@font-face` の定義は件数が多くなるため、Tailwind の出力とは別のファイル（`fonts.css`）に分ける。両方とも自己ホストで、外部ドメインを参照しない。フォント URL は `../fonts/` から始まる相対パスとし、`woff` フォールバックを使わない。
