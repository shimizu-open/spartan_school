## 1. 何を作ったか/誰が何のために使うか

![かけらのコンセプト](./images/01-concept.png)

**一日に一行、心が動いたことを書きとめる Web アプリ。**

- 書くのは一行だけ。何もない日は「なし」ボタンで済む
- 月にひとつ「行ってみる場所」を決める。途中で変えてもいい
- 記録は最初の60日間、直近7日ぶんしか読み返せない。60日経つと全部開く

**誰のため**:日記は続かないが、消えてしまう前に一日を一片だけ拾っておきたい人。

**設計の軸は「作らなかった機能」**:通知・連続日数・達成率・励ましを意図的に持たない(続けさせる装置は、途切れたとき圧になるから)。記録は端末内にのみ保存し、外部には一切送らない。

## 2. HTML・CSS・JavaScript の役割分担

![HTML・CSS・JSの役割分担](./images/02-roles.png)

| 担当 | ファイル | 自分のコードでは |
|---|---|---|
| 構造 | `index.html`(39行) | 画面の「空の箱」を4つ置くだけ |
| 見た目 | `styles.css`(81行) | 色・書体・寸法の定義だけ(`--color-sumi: #333c40` 等) |
| 動き | `app/` 15ファイル | 箱の中身を組み立て、ボタンに反応し、保存する |

```html
<!-- index.html の本体。中身はほぼ空 -->
<main>
  <section id="today-view"></section>
  <section id="outing-view" hidden></section>
  <section id="fragments-view" hidden></section>
  <section id="about-view" hidden></section>
</main>
<script type="module" src="./assets/app/main.js"></script>
```

**ポイント**:変わらない骨組みだけを HTML に書き、変わる中身は JS が組み立てる。画面切り替えは箱の表示/非表示の入れ替え(SPA)——ページを読み込み直さないので一瞬で切り替わり、オフラインでも動く。

![SPAの仕組み](./images/03-spa.png)

## 3. JavaScript のどこで何が起きているか

「記録する」を押した瞬間の流れ。**常にこの一方通行の一本道**で、逆流の道はない。

![クリックからのデータの流れ](./images/04-flow.png)

```
クリック
 → today.js:  入力を取り出し、空チェックし、saveEntry() に依頼(自分では保存しない)
 → state.js:  commit() がデータの塊を丸ごと新品に差し替える
 → local.js:  localStorage に書き込む(ここまで通信ゼロ)
 → state.js:  「変わったよ」と購読者に通知
 → main.js:   render() が呼ばれる
 → today.js:  記録カードの画面を作り直す → 画面が変わる
```

- 「1日1件」はコードでなく**データの形で強制**(`entries` の見出しが日付そのもの)
- ユーザーの文字は `textContent` 経由でのみ画面に入れる(XSS 対策)
- どこが壊れても、この一本道を上から辿れば原因に行き着く

## 4. なぜ Tailwind をビルドして公開したのか

![CDN方式とビルド方式の違い](./images/05-tailwind.png)

| | CDN 方式 | ビルド方式(採用) |
|---|---|---|
| CSS を作る場所 | 利用者のブラウザで毎回 | 手元で一度だけ |
| 利用者に届くもの | Tailwind 本体(数百KB) | 使ったぶんの CSS(**14KB**) |
| 外部通信 | 毎回発生 | ゼロ |
| 公式の位置づけ | 開発用(本番非推奨) | 本番の正式な方法 |

**決定打**:このアプリは CSP(`connect-src 'none'`)で外部通信を全面禁止しているため、CDN 方式は不利どころか**動かない**。

**node_modules を上げない理由**:あれは工場の機材であって製品ではない。完成品 `dist/` には成果物だけが入り、機材は `package-lock.json` から `npm ci` でいつでも再現できるので、Git にも S3 にも置かない。

![ビルドと公開の全体像](./images/12-build.png)

## 5. 本番 URL が表示されるまでに何が起きているか

![URLから画面表示までの道のり](./images/06-journey.png)

```
① DNS(Route 53)   名前 → 住所の変換。「その名前は CloudFront です」と答える
                    (3〜4週目のサブドメイン委任 = この電話帳の管轄を渡す作業)
② CloudFront       一番近い配達拠点に HTTPS で接続。写しがあれば即返す
③ S3               大元の倉庫。非公開で、読めるのは自分の CloudFront だけ
④ ブラウザ          届いた HTML が CSS と JS を追加要求 → 組み立てて表示
```

- `index.html` だけキャッシュ「毎回確認」(古い入口が配られ続けるのを防ぐ)
- 表示された後は端末内で完結。**以後サーバーとの通信はゼロ**
