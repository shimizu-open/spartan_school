1この回でやっていること：サーバーを置く「場所」を作る

この回ではサーバーは1台も作りません。次の回でサーバー（EC2）を置くための場所を用意しているだけです。「何がしたいか」から逆算すると、こうなります。

逆算必要なものどの回
友達に URL を送って、メモアプリを見せたい――
→ 24時間動いていて、インターネットから届くコンピュータが要るEC2②
→ そのコンピュータを置く、ネットワーク上の場所が要るVPC・サブネット①（今回）
→ その場所がインターネットにつながっている必要があるIGW・ルートテーブル①（今回）

AWS は「置く場所が無いとサーバーを作れない」ので、場所づくりが最初に来ています。

2作る4つのもの：自宅のネットワークに置き換える

自宅では、買ってきたルーターがこの4つを全部やってくれています。AWS ではそれを1つずつ手で作ります。

AWS で作るもの自宅で言うと無いとどうなるか
VPC自宅の Wi-Fi のネットワーク全体サーバーを置く場所が無い
サブネットその中の部屋分けVPC の中のどこに置くか指定できない
IGW（インターネットゲートウェイ）回線につながる出入口外と一切つながらない
ルートテーブル「外あての通信は出入口へ送る」という決まり出入口があっても、誰もそこへ向かわない
作る順番にも理由があります。 サブネットは VPC の中に作るので VPC が先。IGW は VPC に取り付けるので VPC が先。ルートテーブルは「IGW へ送る」と書くので IGW が先。後ろのものは、前のものを材料にしています。

3出来上がりの形

緑の線が「インターネットへ出られる道」です。上の2つ（パブリック）にだけ届いています。下の2つ（プライベート）には道がありません。

今回のアプリで実際に使うのは memo-public-1a の1つだけです。
プライベートの2つと、AZ が 1c のほうは、今回は使いません。「サーバーを増やすときに必要になる定石の形」として先に作っています。ここが腹落ちしなくても、先に進めます。

4IPアドレスは、スイッチ32個でできている

IPアドレスは、ネットワークにつながる機械に1つずつ付く番号（住所）です。10.0.0.5 のように、. で区切った4つの数字で書きます。

スイッチ1個 ＝ 1ビット

コンピュータの中には、0 か 1 のどちらかしか入らない箱が並んでいます。この箱1個を「1ビット」と呼びます。オフ（0）かオン（1）かのスイッチだと思ってください。スイッチが1個増えるごとに、表せるパターンは倍になります。

スイッチの数並べ方パターン数
1個0、12
2個00、01、10、114
4個0000 〜 111116
8個00000000 〜 11111111256

256通りに 0 から番号を振ると 0〜255。IPアドレスの数字1つが 0〜255 なのは、スイッチ8個で表しているからです。

数字が4つあるので、全部で32個

10.0.0.5 をスイッチで書いたもの。人間が読みやすいように、8個ずつ区切って数字に直したのが、ふだん見ている IPアドレスです。

5CIDR は「範囲」の書き方。/ の後ろは固定するスイッチの数

VPC を作るとき、「このネットワークではこの範囲の番号を使います」と AWS に伝えます。毎回「〜から〜まで」と書くのは長いので、短く書く方法が決まっています。それが CIDR（サイダー）です。

10.0.0.0 〜 10.0.0.255   ←→   10.0.0.0/24

/ の後ろの数字は、「左から何個のスイッチを固定するか」です。固定した残りが、自由に使える部分になります。

数字1つがスイッチ8個なので、8・16・24 は切れ目がちょうど数字の境目に来ます。

書き方固定される部分範囲個数
10.0.0.0/81010.0.0.0 〜 10.255.255.255約1,677万
10.0.0.0/1610.010.0.0.0 〜 10.0.255.25565,536
10.0.0.0/2410.0.010.0.0.0 〜 10.0.0.255256
固定する部分が長いほど、自由な部分が減って、範囲は狭くなる。「/ の後ろが大きいほど狭い」はここから来ています。
個数は、自由なスイッチの数（32 − / の後ろ）だけ 2 をかけたものです。/24 なら自由が8個で 256、/20 なら自由が12個で 4,096。

6/20 は、3つ目の数字の「途中」まで固定する

VPC は 10.0.0.0/20 で作ります。20 は 16 と 24 の間なので、切れ目が数字の途中に来ます。左から20個数えてみます。

20 ＝ 8 ＋ 8 ＋ 4。1つ目と2つ目の数字は丸ごと固定、3つ目の数字は前半4個だけ固定になります。

「前半4個を固定する」と自分で指定した覚えはなくて当然です。 /20 と入力したとき、左から20個目がたまたま3つ目の数字の真ん中に来た、という結果です。

だから、3つ目の数字は 0〜15 しか取れない

VPC を 10.0.0.0/20 と書いたので、3つ目の数字は 0 ＝ 00000000。その前半4個（0000）が固定されます。動かせるのは後半4個だけです。

スイッチ（前半4個は固定）3つ目の数字
0000 00000
0000 00011
0000 00102
……
0000 111115（最大）

16 にするには 0001 0000 が必要ですが、これは固定されている前半を動かさないと作れません。だから 16 以上にはならない。

10.0.0.0/20  ＝  10.0.0.0 〜 10.0.15.255     （16 × 256 ＝ 4,096個）

7VPC とサブネットの関係：大きい範囲を、小分けにする

サブネットは「VPC の範囲を、さらに小分けにしたもの」です。小分けにするので範囲は VPC より狭い。範囲が狭い＝固定するスイッチが多い＝/ の後ろが大きい。だから VPC が /20 で、サブネットが /24 です。

住所で言うと決まっている部分
VPC /20「〇〇市」市まで
サブネット /24「〇〇市 △△町」市 ＋ 町
サーバー1台「〇〇市 △△町 5番地」全部

VPC では自由だった12個を、サブネットでは「どの区画かを決める4個」と「サーバーに配る8個」に分けて使います。4個で16通りなので、区画は最大16個。4,096 ＝ 16区画 × 256個。

今回の4つのサブネット

「真ん中の4個を決める」のと「3つ目の数字を 0〜15 から1つ選ぶ」のは同じことです。/24 のサブネットを1つ作るたびに、3つ目の数字を1つ選んでいます。

サブネットCIDR範囲選んだマス
memo-public-1a10.0.0.0/2410.0.0.0 〜 10.0.0.2550
memo-public-1c10.0.1.0/2410.0.1.0 〜 10.0.1.2551
memo-private-1a10.0.8.0/2410.0.8.0 〜 10.0.8.2558
memo-private-1c10.0.9.0/2410.0.9.0 〜 10.0.9.2559
  • パブリックは 0 番台、プライベートは 8 番台。16マスの左半分と右半分に分けて置いているので、CIDR を見ただけでどちらか分かります。
  • 3つ目の数字を 16 以上にすると（10.0.16.0/24 など）VPC からはみ出すので、AWS にエラーで断られます。
  • サブネットは /24 でなくても作れます。決まりは「VPC より狭いこと」だけ。/24 は「3つ目の数字＝区画の番号、4つ目の数字＝サーバーの番号」と読みやすいので、よく使われます。

8最後の数字（0〜255）は、サーバーを置いたときに配られる

10.0.8.37

部分意味いつ決まるか
10.0どの VPC かVPC を作ったとき
8どのサブネット（区画）かサブネットを作ったとき
37その区画の中の、どの1台かサーバーを置いたとき（AWS が自動で付ける）

サブネットが「町」なら、最後の数字は「番地」です（建物と部屋のたとえなら、部屋の中に置いた機械1台ずつの番号です）。町を作っただけでは番地は使われません。次の回で EC2 を作るとき、「どのサブネットに置くか」を選ぶと、AWS がその範囲から空いている番号を1つ選んで付けます。自分で番号を考える必要はありません。

256個すべては使えません。
各サブネットで5個（.0、.1、.2、.3、.255）を AWS が予約しています。配れるのは251個。コンソールに「利用可能な IPv4 アドレス：251」と出るのはこのためです。
この番号は VPC の中だけで通じます。
10. で始まる番号は「内部専用」と世界で決められているので、インターネットからは届きません。外から届く番号は別に付きます（下の表）。
番号の種類例どこで通じるかどこで設定したか
プライベートIP10.0.0.37VPC の中だけサブネットの CIDR から自動
パブリックIP54.xxx.xxx.xxxインターネット全体「パブリック IPv4 アドレスの自動割り当て」のチェック。次の回で Elastic IP に置き換える

9ルートテーブル：パブリックとプライベートの違いは1行だけ

ルートテーブルは「この番号あての通信は、どこへ送るか」の表です。ここにも CIDR が出てきます。

memo-public-rt
  10.0.0.0/20 → local      VPC の中の番号あては、中でそのまま届ける（最初から入っている）
  0.0.0.0/0   → memo-igw   それ以外の全部（＝インターネットあて）は、出入口へ
  • 0.0.0.0/0 は「固定するスイッチが0個」。何も固定しない＝全部の IPアドレスという意味です。
  • 2行とも当てはまるときは、範囲が狭いほう（/ の後ろが大きいほう）が優先されます。だから VPC の中あての通信は IGW に行かず、中で届きます。
付いているルートテーブル0.0.0.0/0 → memo-igw の行結果
パブリックの2つmemo-public-rtある外に出られる
プライベートの2つメインのルートテーブルない外に出られない
この回で一番大事な1点。 サブネットに「パブリックにする」というスイッチはありません。IGW への道案内が付いている区画を、結果的にパブリックと呼んでいるだけです。違いは、道案内が1行あるかどうかだけ。
IGW を作っただけでは通れません。 ①作る、②VPC にアタッチする（取り付ける）、③ルートテーブルに「外あては IGW へ」と書く、④そのルートテーブルをサブネットに関連付ける。この4つが揃って、初めて道がつながります。

症状まず疑うところ
さっき作ったものが一覧に無い右上のリージョンが「東京」になっているか。リージョンごとに中身は完全に別です
サブネットや IGW の作成画面で選ぶ VPC が2つある必ず memo-vpc を選ぶ。名前が空のほうは最初からあるデフォルト VPC です

11確認問題

Q1. 10.0.0.0/16 は、左から何個が固定で、どの数字が変えられますか。

16個が固定、16個が自由。1つ目と2つ目（10.0）が固定で、3つ目と4つ目が変えられます。範囲は 10.0.0.0 〜 10.0.255.255。

Q2. 10.0.1.37 という番号のサーバーは、4つのサブネットのどれに入っていますか。

memo-public-1c（10.0.1.0/24）。3つ目の数字が 1 だからです。

Q3. 10.0.5.0/24 は memo-vpc の中に作れますか。

作れます。3つ目の数字 5 は 0〜15 の範囲内で、まだ使っていない5番のマスです。

Q4. 10.0.20.0/24 を memo-vpc の中に作ろうとすると、どうなりますか。

エラーになります。3つ目の数字 20 は 15 を超えていて、VPC の範囲（10.0.0.0 〜 10.0.15.255）からはみ出すからです。

Q5. memo-private-1a に置いたサーバーが、インターネットに出られないのはなぜですか。

付いているルートテーブル（メイン）に 0.0.0.0/0 → memo-igw の行が無いからです。インターネットあての通信の送り先が決まっていません。
