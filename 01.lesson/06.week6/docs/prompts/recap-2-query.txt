情報量が多いので、2枚目の添付（_style-dense.png）の密度で作る。上から「タイトル」「上段：問い合わせの流れ（4つのパネル）」「下段：返ってくる形と、中のつながり」「最下部の一行」。

【上部タイトル】
非常に大きな濃紺のセリフ体：データを取り出すしくみ
その下：Laravel がデータベースに問い合わせて、結果を返すまで
左上に手書き風：書いた瞬間には、まだ何も起きていない。
右上に手書き風：返ってくる形を知っておこう。

【上段：横並びの4パネル。太い青い右向き矢印で 1→2→3→4 とつなぐ】
各パネルの上に小さな絵、その下に見出しと説明。

パネル1　青い枠。大きな番号丸「1」。
見出し：条件を書く
小さな絵：猫が小さなメモ帳に書きとめている。
コード枠：Model::where(...)->orderBy(...)
説明3行：
条件を、Laravel の中のリストに書き足すだけ。
値は、別の場所にしまっておく。
まだデータベースには問い合わせていない。

パネル2　緑の枠。大きな番号丸「2」。
見出し：SQL の文章にする
小さな絵：猫が、空欄が2つある白いカードに文章を書いている。
説明2行：
SQL は書く順番が決まっている。Laravel が決まった順に並べるので、書いた順は関係ない。
横並びの札を矢印でつなぐ（札の中は英字）：select → from → where → order by → limit
説明1行：値の場所は ? にしておく。toSql() で確認できる。

パネル3　琥珀色の枠。大きな番号丸「3」。
見出し：値を、データベースに合う形に直す
小さな絵：猫が、色つきの小さなタイルを磨いている。
説明3行：
MySQL には true / false の型が無く、1 / 0 の数で保存している。
だから送る直前に、true は 1、false は 0 に直す。
where(列, true) は「列 = 1」という条件になる。

パネル4　紫がかった青の枠。大きな番号丸「4」。
見出し：ここで初めて問い合わせる
小さな絵：猫が、データベースを表す青い円筒からカードの束を受け取っている。
説明2行：
文章と値を別々に送る（プリペアドステートメント）。
get() などを呼んだときに、ここまでが一気に動く。

【下段：左の大きな囲み（幅の約2/3）】
帯の見出し（左端に水彩の濃紺の帯）：返ってくる形と、中のつながり
左に4段の表（左列はコード枠、中央は「返ってくるもの」、右は「中でやっていること」）：
get()　｜　複数件の入れ物（コレクション）。0件なら空の入れ物　｜　行をモデルに変えて、入れ物に入れる
first()　｜　1件そのもの。無ければ null　｜　「1件だけ」の条件を付けて get() → 先頭を取り出す
find()　｜　find(2) なら id が 2 の行を1件。無ければ null　｜　「id が 2」の条件を付けて first()
pluck()　｜　1つの列の値だけの一覧　｜　get() は使わない。その列だけを取る SQL を直接実行し、モデルは作らない
表の右に、縦のつながり図（白いカードを矢印でつなぐ）：
find() → first() → get() → 「SQL を実行する共通の部分」
pluck() → 「SQL を実行する共通の部分」（get() を通らない別の道として、横から直接つなぐ）
図の下に、小さな囲み（白地、濃紺の細枠、見出し「find(2) の中身」）：
コード枠（1行）：whereKey(2) → first()
2行の説明：
2 は「どれを探すか」（id が 2 の行）。first() は「何件返すか」（1件だけ取り出す）。
first は「1番目の記事」という意味ではない。id は重ならないので、結果は0件か1件。箱から出して1件で渡している。
（find(2) と whereKey(2) と first() はコード枠の中に描く）

【下段：右の付箋（淡い黄色、ピン止め）】
※ よくあるエラー
入れ物のまま ->title を読もうとする。
null のまま ->title を読もうとする。
見つからないかもしれないときは findOrFail() を使う。
（->title と findOrFail() はコード枠の中に描く）
