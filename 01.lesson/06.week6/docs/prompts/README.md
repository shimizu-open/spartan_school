# インフォグラフィック生成メモ

水彩イラスト風のポスターは Codex CLI の画像生成で作っている。

```bash
cd docs/images
codex exec -C "$PWD" -s workspace-write --skip-git-repo-check \
  -i _style-clean.png -i _style-dense.png -i _ref-cat.jpg \
  < ../prompts/di-infographic.txt
```

## プロンプトの使い分け
| ファイル | 構成 |
|---|---|
| `di-infographic.txt`       | 6コマで「なぜ届くのか」のしくみを追う（確定版） |
| `di-infographic-compare.txt` | 上下2段で BEFORE / AFTER を絵で比較 |
| `di-infographic-scene.txt` | レストラン店内を一枚絵にして左右で対比 |
| `di-infographic-4koma.txt` | DIの流れだけを4コマで追う |

### 学習まとめ（recap）

```bash
bash docs/gen-recap.sh recap-1-trust recap-2-query recap-3-undo
```

| ファイル | 構成 |
|---|---|
| `recap-1-trust.txt` | 届いたデータを、そのまま使わない（`$fillable` / プリペアドステートメント） |
| `recap-2-query.txt` | データを取り出すしくみ（問い合わせの流れ / 返ってくる形） |
| `recap-3-undo.txt`  | あとから元に戻せるように作る（`down()` / 論理削除） |

猫が別キャラ（子猫・白い顔）に化けたことがあるため、水彩の猫先生の見本 `_ref-cat-watercolor.png` を常に添付している。

共通の前後文は `_recap-common-head.txt` / `_recap-common-tail.txt`。添付は `_style-clean.png` `_style-dense.png` `_ref-cat.jpg`。

## 添付画像の役割
| ファイル | 役割 |
|---|---|
| `_style-clean.png` | 画風とレイアウトのお手本（白基調・余白多め）。最優先で寄せる |
| `_style-dense.png` | 情報密度と細部の作り込みのお手本 |
| `_ref-cat.jpg`     | キャラクター（青い猫）の顔と配色の基準 |

## ハマりどころ

- `-i` は可変長引数。プロンプトは**必ず標準入力から**渡す。
  引数で渡すと `-i` に飲み込まれ「No prompt provided via stdin.」で無言終了する。
- **小さく描かれる文字は化ける。** 実例（没にした版）:
  言葉→言薬 ／ 動く→敷く ／ 書く場所→聞く場所 ／ 種類→種頬
  → 文字ブロックを隅に小さく押し込まず、幅をとって大きく置くよう指示すること。
- **画数の多い漢字は へん を取り違えることがある。** 実例: 給仕 → 銟仕（糸へんが金へんに）。
  → 言い換えられる語は言い換える（給仕 → 執事）。同じ役を2通りに呼ばない副産物もある。
- **引用符が密集したコードは化ける。** 実例: `"... col = '" . $input . "'"` → `. ''"`。
  → 同じ意味で引用符の少ない書き方に変える（`"... col = '$input'"`）。
- **`->` が矢印記号 `→` に化ける。** → 「半角ハイフンと半角 > の2文字」と明示する。
- **Codex が生成後に Pillow で文字を重ね書きすることがある。** 文字の重なり・白いつぎはぎ・活字の混在が出る
  （3072×2048 など、指定外のサイズになっていたら疑う）。
  → 「画像生成ツールの出力をそのまま保存。文字の重ね書き・拡大・加工をしない」と明示する（gen-recap.sh に組み込み済み）。
- 文字量を減らして絵を主役にすると、化けるリスクも同時に下がる。
- **記号も化ける。** 実例: `/articles/{article}` → `/articles/{article)`（閉じ波括弧が丸括弧に）。
  → 記号を含む文字列は、地の文に置かず**コード枠の中**に入れる。
  コード枠の中身はこれまで一度も崩れていない。最も信頼できる置き場所。

## 内容についての反省（recap）

- 会話の中で説明のために使ったたとえ（「列の枠」「メモ → 清書」「欄と係」「裏口」など）を見出しにすると、
  前後の説明を知らない人には意味が通じない。
  → 各項目を「どんな場面で → 何が起きて → なぜ → どうする」の順に組み直し、普通の言葉で書く。
  専門用語は、中身を説明したあとに「これを〇〇と呼ぶ」で出す。
- 表の絵を指示すると、勝手に人名やメールアドレスを入れてくる。
  → 「表の絵は罫線だけ、セルは空」「具体的なデータの値は絵の中にも描かない」と明示する。

## 内容についての反省

絵として成立しても「なぜそうなるか」が無いと資料として使えない。
DI の場合、最低限これを描かないと説明したことにならない:
1. メソッドが動く**前**に Laravel が引数を読んでいる
2. 型に書いたクラス名がどのテーブルを見るかの目印になる
3. どの列で探すかはモデルの `$primaryKey` が決めている
   （`id` と書いていないのに `id` で探せる理由）
- 引用符は放っておくとカーリークォート（’）になる。
  「まっすぐな半角のシングルクォート（'）にすること」と明示する。
- 画風は指示しないと「緑の葉が全面・猫が巨大・高彩度」に振れる。
  「背景は白基調」「水彩は画面の縁だけ」「猫は画面の1/8以下」と数値で縛る。
