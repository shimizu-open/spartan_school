MIGRATION ROLLBACK ・ SOFT DELETES
作る前に、戻し方を書いておく。消す前に、残し方を決めておく。
1

マイグレーションは「行き」と「帰り」の対

down() が正しいかは、往復させて確かめる
up() の変更を、down() でちょうど元に戻す。
足した列は消す、作った表は消す。
コマンドやることdown() の確認
migrate:rollback直近のまとまりの down() だけ実行。--step で数を指定1つずつ確かめる
migrate:refresh全部 down() → 全部 up()。エラーなく往復できれば対になっているまとめて確かめる
migrate:freshdown() を呼ばずに全テーブルを削除 → 全部 up()確認にならない
migrate:statusどれが実行済みで、どれが未実行かを一覧で見る結果の確認に
2

同じ削除コードでも、意味が2通りある

初期状態は物理削除
物理削除：行そのものを消すDELETE
$model->delete();
// → delete from `表` where …
// 初期状態はこちら。二度と戻せない
シュレッダーにかける。復元はできない
▶
印をつけて残す
論理削除：「消した」印をつけるSOFT DELETE
$model->delete();   // 書き方は同じ
// → update `表` set `deleted_at` = 現在時刻
// 普段の検索からは自動で外れ、あとで戻せる
保管箱にしまう。必要なら取り出せる
3

論理削除が成り立つ条件

欄と係、両方そろって初めて動く
欄印を書く場所
マイグレーションで deleted_at 列を足す（softDeletes()）
＋
係印を書く人
モデルに SoftDeletes を付ける。削除を「印つけ」に差し替える
＝
削除のコードはそのままで、
論理削除に変わる
係だけ（欄が無い）印を書く場所が無く、列が無いエラーで止まる
欄だけ（係がいない）誰も印を書かないので、物理削除のまま
裏口 DB::table()モデル（係）を通らないので、係がいても物理削除になる
withTrashed()削除済みも含めて取る onlyTrashed()削除済みだけ取る restore()印を消して復元 forceDelete()論理削除モードでも本当に消す
まとめ
「消す」「変える」の前に、戻る道を用意しておく。
構造の戻り道は down()、データの戻り道は論理削除。どちらも、往復できるかを実際に試して確かめる。
