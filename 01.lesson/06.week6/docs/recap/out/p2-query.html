LARAVEL / PHP ・ VISUAL ABSTRACT 2/3

クエリは「メモ → 清書 → 実行」

QUERY BUILDER ・ RETURN TYPES
書いた順ではなく、決まった形に組み立てられる。返ってくる形も、メソッドで決まる。
1

メソッドをつなげている間、SQL はまだ無い

注文票にメモを溜めて、最後に清書する
メモ

条件を溜めるだけ

where() や orderBy() は、条件を内部の一覧に書き足すだけ。この時点では DB に何も聞いていない。

清書

SQL の文法どおりに並べ直す

メモを決まった順番に当てはめて1つの文章にする。書いた順は関係ない。

select→from→where→order by→limit
実行

穴あきの文と、値を別々に渡す

値の場所は ?。値は直前に DB 向けに整えられる（例：真偽値は 1 / 0 の数になる）。

Model::where(…)->orderBy(…)   // メモを溜める
     ->toSql();                 // 清書を見るだけ（実行しない）
// → select * from `表` where `列` = ? order by `列` desc
     ->getBindings();           // ? に入る予定の値
2

返ってくる「形」が、メソッドごとに違う

箱で渡すか、1個で渡すか、値だけ渡すか
メソッド返ってくるもの見つからないとき中でやっていること
get()箱（Collection）に入ったモデル空の箱条件に合う全部を取る
first()モデル 1個null1件に絞って get() → 先頭を取り出す
find()モデル 1個（主キーで探す）null主キーの条件を足して first()
pluck(列)その列の値だけの箱空の箱モデルは作らない。その列だけ取る
!箱に列名は無い
箱に ->列名 は使えない。pluck で抜き出すか、foreach で1個ずつ。
!null に要注意
1個で返るものは、無いと null。確認するか findOrFail() で 404 に。
i配列を渡すと箱
find() に複数の主キーを渡すと、複数件になるので箱で返る。
3

実行の瞬間に、裏で起きていること

get() や first() を呼んだとき
1

清書する

文法係がメモを決まった順に並べ、値の場所を ? にする

2

値を DB 向けに整える

真偽値は数に、日時は文字列に。PHP と DB の違いを吸収

3

穴に値をセットして実行

プリペアドステートメントで、文と値を別々に渡す

4

結果を形にして返す

行をモデルにして箱へ。1個で返すものは、そこから先頭を取り出す

1件か複数件かを決めているのは、DB ではなく Laravel の作り。DB から取ってくる処理は get() の1か所だけで、
first() も find() も、箱の先頭を取り出して渡す一手間を足しているだけなのじゃ。箱が空なら、取り出せずに null。
まとめ
メモを溜め、清書して、1回だけ聞きに行く。
SQL が作られるのは最後の瞬間。値は ? と別便で届く。返り値は「箱」「1個」「値の箱」の3つの形を見分ける。
